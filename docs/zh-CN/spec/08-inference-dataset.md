# ScrambNet 规范 —— 第 8 部分：推断数据集

> **非规范性翻译。** 规范版本以英文为准（[en](../../en/spec/08-inference-dataset.md)）。

**状态：草稿（DRAFT），且是一项已声明的研究风险。** 本部分决定客户端如何
获取第 3 部分据以推断的 IP-to-AS（以及粗粒度司法辖区）映射（PS-4），其约束
是 I-3 —— 没有权威 —— 面对的是在除哈希或签名所绑定之物以外的一切事情上都
撒谎的中继与数据集宿主。被标记为 `(s)` 的是 strawman 值。该映射用于不相交性
验证的*用途*是 OP-1；它的*分发*是 roadmap 条目 2.3。

头号决定在 §1 中陈述，并在其后各节加以辩护。先读 §1 与 §9（残余）：二者合起来
说明了本部分买到了什么，又承认了它买不到什么。

## 1. 这一决定，用两句话

- **没有规范（canonical）映射，也没有映射权威。** 该数据集是一个
  **可复现、内容寻址的产物（artifact）**，任何一方都能从公开输入逐字节地
  将其重建；两个客户端取得一致，不是因为它们信任某个签名者，而是因为它们
  算出了**相同的哈希**（ID-1、ID-5）。一个由固定集合签名的规范根就是换了名字的
  目录权威，而 I-3 禁止它。
- **一致由复现达成；发布经由一个任何人都可写入的仅追加透明性日志；首次取回时的
  信任是 TOFU，并被如此声明。** 该日志并不*册封*某个映射 —— 它为之加盖时间戳，
  并使含混其辞（equivocation）可被检测（ID-6、ID-7）。一个崭新客户端的第一个映射
  是一个「首次使用即信任」的时刻，日后的 gossip 让它得以**检测**出其为坏，
  而非**阻止**（§7）。

所以 roadmap 标记出来的那个坦诚结局才是真正的结局：**TOFU 映射 +
透明性日志 + 异常 gossip，而非一个规范映射。** 以下的一切都是把「自己复现它，
并检测出任何撒谎者」具象化的构造，而 §9 是任何构造都无法消除的残余。

## 2. 范围，以及本部分所要规避的陷阱

第 3 部分（PS-4、PS-5）要求每个客户端*从一个中继的 `addrs`*、使用客户端**自己的**
数据集去推断其 AS 与粗粒度司法辖区，而绝不采用中继的自我申报（GR-3）。本部分只
关乎**该数据集从何而来，以及两个客户端如何知道自己持有的是同一个**，而在整条链条
—— 构建、发布或 bootstrap —— 中的任何一处都没有一个受信任的方。

这个陷阱很微妙，必须点名：最省事的「无信任」设计是一份由一小撮维护者发布的、
经签名的规范快照。那恰恰就是本项目对中继自我否决掉的那个 Walking-Onions 权威
（GR-1 范围），如今又被改头换面地重新偷运回来用于地理。一个映射签名者若能悄悄
发出一份把某一段 AS 标错的映射，就能让对手的同址（co-located）中继对每个客户端
*看起来*是不相交的 —— 这是一次地理粒度上的日蚀（eclipse），它击溃第 3 部分的
确定程度不亚于一份坏的中继目录。所以签名者集合就是威胁，而本设计不得拥有一个
具备那种权力的集合。

- **ID-1（没有映射权威）。「[规范性]」** 获取、校验或更新该数据集的任何一步，都
  必须（MUST）不要求信任某个特定的方制作、签名或册封了该映射；等价地说，获取与
  校验该映射必须（MUST）能仅用不受信任的替代物完成。唯一受信任的操作是：
  (a) 重新计算一个哈希，以及 (b) 从公开输入重建该产物并加以比对。任何无法被一个
  执行 (a) 或 (b) 的不受信任替代物所取代的设计要素，依据 I-3 即为缺陷，且必须（MUST）
  被移除或在 §9 中声明。

## 3. 该映射是什么

- **ID-2（产物形态）。** 该数据集是单一的压缩产物，即**映射**，针对 IPv4 与 IPv6
  空间，包含：
  - 一张 **IP 前缀 → 源 AS（origin-AS）** 表（最长前缀匹配查找），以及
  - 一张 **AS → 粗粒度司法辖区** 表，其中「司法辖区」是从 RIR 分配派生的
    **国家级**标签，刻意保持粗粒度 —— 更细的粒度是本部分不会假装去解析的噪声（§9）。
  该映射携带一个自描述头部：格式版本 `1`、快照 **epoch**（ID-4）、确切的输入清单
  （manifest，ID-3），以及构建工具版本。该产物以 `H = BLAKE2s(artifact)`（套件哈希，
  第 0 部分）寻址；`H` 是该映射唯一的名字。不存在任何可以用来替代 `H` 而被信任的
  人类可读版本字符串。
- **ID-2a（查找是全（total）的）。** 每一次查找都必须（MUST）返回一个具体的
  `(AS, jurisdiction)`，或者返回显式值 **`unknown`**。`unknown` 是一等答案，不是
  错误，而第 3 部分（PS-5）已对其做保守处理（`unknown` 与一切共享）。该映射不得
  （MUST NOT）为了回避一个 `unknown` 而猜测；一个捏造的答案比一个被承认的缺口
  更糟，因为它会悄无声息地击溃 PS-5。

## 4. 该映射如何构建（可复现地，从公开输入）

构建是一个**从具名公开输入到逐字节相同产物的纯函数**。确定性就是整场游戏的全部：
如果两个诚实的方可能产生分歧，哈希相等（ID-5）便不再意味着「同一个映射」，设计
也就塌缩为需要一个权威来打破平局。

```
  公开输入（在清单中按内容哈希钉定，ID-3）
  ┌────────────────────────┐   ┌────────────────────────┐
  │ RouteViews + RIPE RIS  │   │ 5 份 RIR 委派文件      │
  │ BGP MRT RIB 转储       │   │ （AS → 国家）          │
  │ （前缀 → 源 AS）       │   │                        │
  └───────────┬────────────┘   └───────────┬────────────┘
              │   epoch = ≤ 00:00 UTC 边界的最后转储（ID-4）
              └───────────────┬───────────────┘
                              ▼
            ┌───────────────────────────────────┐
            │  确定性构建（纯函数）             │
            │  固定顺序（ID-4a）、固定破平局    │
            │  （ID-4b）、无浮动输入（ID-4c）、 │
            │  规范容器（ID-4d）                │
            └─────────────────┬─────────────────┘
                              ▼
                         映射产物
                              │
                              ▼
                   H = BLAKE2s(artifact)   ← 映射唯一的名字（ID-2）

  Alice ─ 相同输入 ─▶ H_A        钉定相同输入的两个诚实方得到
  Bob   ─ 相同输入 ─▶ H_B        H_A == H_B。一致即哈希相等
                                  （ID-5），而非信任某个签名者。
                                  复现即仲裁者。
```

- **ID-3（公开输入，按内容钉定）。「[规范性]」** 该映射必须（MUST）只从这样的输入
  构建：它们是公开的、可复现的，并且本身在产物清单中以各自的哈希被内容钉定：
  - 用于源 AS 的 **BGP 路由表**：**RouteViews** 项目的采集器与 **RIPE RIS** 采集器
    （MRT `RIB` 转储）。这些是标准的公开、多视点 BGP 归档；同时使用两个项目的多个
    采集器，本身就是一项多样性措施（没有哪个单一采集器的视角是权威的，ID-3a）。
  - 用于 AS → 国家映射的 **RIR 委派统计**：五家 RIR 发布的 **delegated-extended**
    文件（ARIN、RIPE NCC、APNIC、LACNIC、AFRINIC）。它们在无人自我申报的情况下，
    给出 AS 号与地址块的分配国家代码。
  该清单必须（MUST）以与 URL 无关的内容哈希、以及其来源所述的时间戳，列出每一个
  输入文件，从而由输入 —— 而非某台服务器 —— 定义构建。一方通过用这些哈希从**任意**
  镜像取回输入来重建（I-3：来源可替换；字节已钉定）。
- **ID-3a（多视点源解析）。** 一个前缀的源 AS 必须（MUST）按一条固定规则（ID-4b）
  跨**所有**已入清单的采集器解析，而非来自单个采集器。一个在不同视点被观察到源相
  冲突的前缀会被确定性地解析，而在冲突为真之处（MOAS —— 多源 AS），被记录为一个
  **集合**，第 3 部分将其视作「可能是其中任意一个」，即保守地共享（§9）。该映射
  不得（MUST NOT）悄无声息地挑一个。

### 4.1 确定性隐患，以及构建如何将其钉定

下述每一项隐患都是一个两名诚实构建者可能产出不同字节之处。构建过程必须（MUST）
消除每一项；不这样做的构建是不合规的，因为它无法支撑 ID-5。

- **ID-4（快照 epoch —— 转储时点）。「[规范性]」** BGP 与 RIR 数据持续变化，
  因此「当前转储」不是一个函数。构建必须（MUST）钉定单一的 **epoch 边界**：一个按
  固定节律的 UTC 时刻（strawman：以**每周（s）** 为节律的 **00:00 UTC** 快照 ——
  第 0 部分的提交已采用 UTC），并且必须（MUST）对每个已入清单的采集器/RIR，采用
  **其来源所述时间戳 ≤ epoch 边界的最后一次转储**。两名瞄准同一 epoch 的构建者，
  因此无论何时运行都会选中相同的输入文件。该 epoch 既在产物头部（ID-2）中，也在
  `H` 的原像（preimage）中。
- **ID-4a（排序）。** 所有表都必须（MUST）以**固定的全序**发出：前缀按
  （地址族、数值网络地址、前缀长度）排序；AS 条目按数值 ASN 排序；司法辖区按其
  固定的国家代码字符串排序。任何映射迭代顺序、哈希表顺序或输入文件顺序都不得进入
  输出。
- **ID-4b（破平局是被指定的，而非由实现定义）。「[规范性]」** 每一处数据有歧义的
  地方都必须（MUST）有一条写在本部分里的规则，不给实现者留下任何「挑一个」：
  - *跨采集器的源 AS：* 取所观察到的源集合；若它是单个 AS，则发出它；若为多个
    （MOAS），则按升序发出完整集合。绝不按流行度把一个 MOAS 坍缩为一个 AS ——
    那是一次猜测（§9）。
  - *重叠前缀：* 最长前缀匹配的语义通过存储所有前缀来保留；是查找、而非构建，
    来解析特定性（specificity）。
  - *跨 RIR 的 AS 到国家冲突：* 若委派文件在某个 AS 的国家上不一致，则对该 AS 的
    司法辖区发出 `unknown`。公开注册机构之间的分歧恰恰是映射不得凭专断去解析的
    一种情形。
- **ID-4c（禁止浮动输入）。** 构建不得（MUST NOT）查询任何不在清单内的输入 ——
  没有实时 DNS，没有构建期的 WHOIS，没有许可证禁止再分发或不可复现的地理定位
  数据库，没有商业 IP 情报源。输出的每一个字节都可追溯到一个被哈希的公开输入。
  （这排除了那些方便却不可验证的数据源；它们的准确性抵不过它们重新引入的权威。）
- **ID-4d（规范容器）。** 该产物的压缩与封帧必须（MUST）是确定性的（固定编解码器、
  固定级别，容器元数据中没有时间戳或文件名）。构建被指定得足够严密，以至于一个
  合规的构建工具本身就是可复现的（roadmap 4.2），并且必须（MUST）存在一个跨实现的
  **映射测试向量**（一个输入清单 → 预期的 `H`），使得第二个实现能证明它构建出
  完全相同的产物（与 roadmap 3.2 关联）。

## 5. 两个客户端如何就持有同一映射达成一致

- **ID-5（一致即哈希相等，仅此而已）。「[规范性]」** 两个客户端持有同一映射
  **当且仅当**它们的产物哈希 `H` 相等。比对是一次 32 字节的相等检查；它不需要
  签名者，不需要法定人数（quorum），不需要权威。客户端 gossip `H`（ID-8）；相等的
  `H` 是同一映射的证明，不等的 `H` 是它们不同的证明，且必须（MUST）作为一次
  **背离（divergence）**（ID-9）报告给用户，绝不悄无声息地朝任一方和解。
- **ID-5a（重建是仲裁者）。** 当两个客户端对同一 epoch 持有不同的 `H` 时，这场争议
  可由**任何人**解决，无需向权威申诉：从入清单的输入（ID-3）重建，看公开输入实际
  产出哪个 `H`。一个其 `H` 无法从其所述清单复现出来的映射，按定义就不是那些输入的
  映射，且必须（MUST）被拒绝（ID-5b）。正是这条性质让系统得以没有权威：
  *真相是可复现性，而非签名。*
- **ID-5b（拒绝不可复现者）。** 一个拥有输入（或取回它们）的客户端，若发现
  `H ≠ BLAKE2s(rebuild(manifest))`，必须（MUST）丢弃该映射，并应当（SHOULD）
  将该差异作为异常 gossip 出去（ID-10）。一个没有带宽去重建的客户端可以（MAY）
  按 TOFU/共识条款（§6、§7）接受一个映射，但必须（MUST）将其跟踪为**未验证
  （unverified）**，直到它（或一个它随后与之取得一致的对端）完成重建。

## 6. 透明性日志（以及它为何不是权威）

哈希相等告诉两个客户端它们*不同*；它本身并不防御一个给**不同**客户端喂**不同**
映射、并让每个客户端在内部保持自洽的对手 —— 一次**分裂视图（含混其辞）攻击**。
透明性日志的存在恰是为了那个威胁，别无其他。

```
  分裂视图攻击，以及 gossip 如何逮住它

  一个敌意日志试图展示两个永不相遇的视图：

     日志 ──根 X（映射 H_good）──▶  Alice  「我的映射已被佐证」
          └─根 Y（映射 H_bad ）──▶  Bob    「我的映射已被佐证」

  每个客户端单独看都是自洽的故事。但根经由 GR-6 通道被 gossip
  出去（ID-7a），于是某个第三方客户端 Carol 同时听到二者：

        Alice ──根 X──┐
                      ├──▶  Carol 要求在 X 与 Y 之间
        Bob   ──根 Y──┘     给出一致性证明。
                           若 X 与 Y 并非同一棵仅追加树的
                           扩展，则该证明失败：
                           ✗  日志含混其辞的密码学证明
                              → 日志被标为敌对，被 gossip（ID-10）

  日志从不说哪个映射是好的——那由复现来做（ID-5a）。
  它只让同时对不同的人撒谎变得可检测。任何人都可追加
  （ID-7，无需许可），所以日志是一块公告栏，而非权威——
  这正是让它避开 I-3 之所在。
```

- **ID-6（该日志是什么）。** 该日志是一棵**仅追加的 Merkle 树**（RFC 6962 /
  Certificate-Transparency 结构：一棵在叶子序列之上的 Merkle 树，带有包含证明
  （inclusion proof）以及两个树尺寸之间的一致性证明（consistency proof））。每个
  **叶子**是一则映射公告：`(epoch, H, input-manifest-hash)`。日志的状态由其
  **签名树头（signed tree head）**概括 —— 这里，即某个树尺寸下的一个**根哈希**。
  该日志在密码学上证明两件事：某个给定的 `H` **被包含**（包含证明），以及该日志
  **只曾增长、从未改写历史**（一致性证明）。它不证明 `H` 是否是一个*好*映射 ——
  那由复现（ID-5a）来做。
- **ID-7（谁可以追加 —— 无需许可，所以它不是权威）。「[规范性]」** **任何人**都
  可以（MAY）追加一个公告其所构建映射的叶子；不存在特权追加者，不存在许可名单
  （allow-list），不存在其签名使某个映射成为官方的签名者集合。该日志因此**不是**
  那个被信任之物 —— 它是一块**有见证的、防篡改的公告栏**。它唯一的权力是使含混其辞
  *可被检测*；它**无权选择映射**，而这正是让它避开 I-3 禁令之所在。一个把追加设门槛
  在某个签名者集合之后的日志，那就**是**（WOULD be）I-3 禁止的目录权威，这样的设计
  是不合规的（ID-1）。
- **ID-7a（经由 gossip 根实现含混其辞检测）。「[规范性]」** 针对分裂视图的防御
  **不是**信任日志运营者；而是**在既有的 GR gossip 通道上 gossip 该日志的签名树头**
  （GR-6），并对一个客户端所见的任意两个根要求**一致性证明**。如果一个日志竟呈现
  两个并非彼此一致扩展的树头 —— 含混其辞的签名 —— 任何同时观察到二者（直接地、
  或经由某个对端 gossip 来的根）的客户端，便拥有该日志撒了谎的**密码学证明**，且
  必须（MUST）将该日志当作敌对的（ID-10）。因为根被广泛地 gossip（GR-6 混合来源，
  GR-8），一个日志无法长久地向客户端 A 出示根 X 而向客户端 B 出示根 Y，总会有
  某个客户端同时持有二者并逮到它。
- **ID-7b（多个日志，没有一个规范日志）。「[规范性]」** **不存在单一日志。** 客户端
  必须（MUST）支持**若干个独立的日志**，并且只有当一个映射带着一致的 gossip 根、
  出现在该客户端所关注的日志的一个可配置法定人数中时，才将其视作日志佐证
  （log-corroborated）（strawman：**其集合中日志的 ≥2 个（s）**）。这移除了最后一个
  单点：没有哪一个日志运营者是承重的，而一个客户端的日志集合 —— 一如它的中继样本
  —— 是多样的、可替换的（GR-8 的理由应用于日志）。一个熄灭的日志会被绕过，一如
  一个熄灭的中继被绕过那样。
- **ID-7c（日志存储承诺，而非映射）。** 叶子携带 `(epoch, H, manifest-hash)` ——
  几十个字节 —— 绝不是产物本身。映射本身由 `H` 内容寻址地从任意镜像或对端取回
  （ID-8）；日志只证明*哪些* `H` 值曾被公告以及*何时*被公告，从而日志存储保持微不足道，
  也没有哪个日志成为分发瓶颈。

## 7. bootstrap 悖论，坦诚地陈述

一个崭新客户端没有可供它评估的中继样本，也没有先前的映射；它必须在一些其不相交性
它**尚无法验证**的路径上取回其**第一个**映射（那项验证需要它正在取回的那个映射）。
这是一个货真价实的循环依赖，而本部分并不假装打破它。

```
  第一个映射是首次使用即信任（ID-8）——而其损害是有界的

  崭新客户端 ──▶ 在其尚无法评估的通道上取回第一个映射
                 │
                 ▼
      ┌───────────────────────────┐
      │  状态：未验证-TOFU         │  UI：「你正在信任你的第一个
      │  （向用户展示）            │       映射；尚未被佐证」
      └─────────────┬─────────────┘
                    │  在其后若干 epoch 内，二者之一：
       ┌────────────┴─────────────┐
       ▼                          ▼
  从输入重建                 gossip 根 + 对端 H
  （ID-5a）：H 匹配？         在阈值之上一致？
       │                          │
  是 ──┴── 否               是 ──┴── 否（持续背离）
   ▼        ▼                ▼        ▼
 已验证   异常             已验证   异常被 gossip（ID-10），
          （ID-5b,10）               用户被警告（ID-8b）

  即便一个全然敌意的第一映射也是有界的（ID-8a）：
    1. I-2 下界不受触动，但一份*操纵*地图能把对手机动
       到 k 之外（塌缩诚实池，PS-12）→ 对一份未验证地图，
       在约 15% 占有率阈值之上内容「可能」坍落。不是仅
       元数据。由 k/n 余量 + PS-12 防御界定，而非由「不能」。
    2. 暂时且可检测——对手必须永远日蚀客户端才能让其
       保持隐藏（那是 OP-2，而非此处的新弱点）。
    3. 不可伪造——对手无法让公开输入重建出一个坏的 H。
       一次重建、或一个做过重建的诚实对端，即收敛到真相。
```

- **ID-8（bootstrap 是首次使用即信任，并被声明）。「[规范性]」** 一个崭新客户端
  获取的第一个映射是一个 **TOFU** 决定。客户端必须（MUST）在尽可能多的**独立**通道上
  获取它（strawman：GR-10 的带外桥接线路，外加两个或更多经由不同网络抵达的公开
  镜像（s）），在临时接受之前必须（MUST）要求所有通道给出**相同的 `H`**，并且必须
  （MUST）将该映射记录为**未验证-TOFU（unverified-TOFU）**，直至它要么 (a) 从输入
  重建（ID-5a），要么 (b) 在一个置信阈值之上累积到一致的 gossip 根与对端 `H` 一致
  （ID-7a、ID-9）。客户端必须（MUST）把这一状态呈现出来：*你正在信任你的第一个映射；
  它尚未被佐证。*
- **ID-8a（一个坏的第一映射给对手买到什么的界）。「[规范性]」** 一个控制了崭新客户端
  整个首次取回的对手，可以递给它一个把 AS 标错、使同址中继看起来不相交的映射。
  对损害的界是三重的，且必须（MUST）被设计所保全：
  1. **I-2 下界本身不受触动；但一份敌意映射能够通过操纵触及内容。** `k` 以下的
     Shamir 下界是数学性的，一个坏映射无法降低它。一个坏映射*能够*做的 —— 而这更正了
     此前一处过度陈述 —— 是**把对手机动到 `k` 之外**：一份给对手的同址中继以互不相同的
     伪造 AS、并给诚实中继以相互碰撞的伪造 AS 的映射，会塌缩诚实候选池，并把按 AS
     互不相交的选取确定性地操纵到 `≥ k` 条对手链路之上（完整构造及其防御即 **PS-12**；
     已对模拟器演示，在约 15% 占有率下约 100% 的内容攻破）。所以一个坏映射**不是**一次
     仅元数据的攻击：对一个已接受一份未验证映射、且尚无法重建的客户端而言，内容下界
     可能坍落。因此那个诚实的界是有条件的，而非绝对的：一份坏映射触及内容**仅当**
     对手已占有客户端*可达*抽样中足以主宰塌缩后之池的那一份（阈值地带，PS-12），
     **且** PS-12 的防御未被施加。随机的不准确（噪声）对关联的侵蚀仍然远快于对内容的
     侵蚀；一份*被择定*的映射则不然。下面的声称 2 与 3 是让即便这一点也保持有界的东西。
  2. **它是暂时且可检测的，而非永久的。** 客户端一旦 gossip 其根/`H`（ID-9）或重建
     （ID-5a），一个没有任何诚实对端或公开输入佐证的映射便会显眼起来。对手必须把
     客户端**永远**日蚀下去，才能让那个坏映射不被曝光 —— 而那是 OP-2 的日蚀问题，
     并非本部分引入的新弱点。
  3. **它无法伪造复现。** 对手可以发出一个坏的 `H`，但它无法让公开输入重建出那个
     `H`（ID-5a）。一个但凡重建过、或但凡遇到过一个重建过的对端的客户端，都会收敛
     到真实的映射。
- **ID-8b（检测，而非声称阻止）。「[规范性]」** 本部分提供的是**对一次坏 bootstrap
  的事后检测**，而非对它的阻止。一个合规的客户端不得（MUST NOT）把一个 TOFU 映射
  呈现为已验证，必须（MUST）将其作为 gossip 重新评估并（可选地）累积重建，并且
  必须（MUST）在佐证未能在一个可配置窗口内到达时发出警告（strawman：若干个 epoch
  （s)）。「我们无法阻止一个坏的第一映射；我们让让它保持不被检测这件事变得昂贵、
  并最终变得不可能」才是那个坦诚的断言，也是 UI 所陈述的断言。

## 8. 与之共处：刷新与背离处理

- **ID-9（映射新鲜度与 gossip）。** 客户端必须（MUST）朝当前 epoch 的映射刷新
  （ID-4 节律），并且必须（MUST）在 GR-6 批次上 gossip 其当前的 `(epoch, H)` 与它
  持有的日志根，受 GR-8 来源混合约束，从而没有哪一类对端能主宰一个客户端对「哪个
  映射是当前的」的看法（同一套日蚀防御，重用）。客户端不得（MUST NOT）在应用
  GR-8/PS-10 的「只计数独立验证过的来源」规则*之前*，就按有多少对端报告某个映射来
  对其加权 —— 一群 sybil 不能单凭数量把一个坏映射投票进共识（与 OP-2 关联）。
- **ID-9a（背离被展示，而非被隐藏）。** 当一个客户端的 `H` 对同一 epoch 异于一个
  被佐证的法定人数（ID-7b）时，它必须（MUST）将自己的映射视作可疑，尝试重建或
  重新取回，并在第 3 部分既有的诚实界面（PS-9）中向用户报告该背离：*你对网络地理的
  看法与你的对端相左；不相交性判断可能是错的。* 此处的沉默会让一次地理日蚀不被察觉
  地运行。
- **ID-10（异常 gossip）。「[规范性]」** 有三个事件是每个客户端在检测到时都必须
  （MUST）gossip 的**异常**，因为它们是本部分无法阻止、只能揭示的那些攻击的可观察
  签名：(a) 一个无法从其清单复现的 `H`（ID-5b）；(b) 一个呈现不一致的根、即已证实
  含混其辞的日志（ID-7a）；(c) 一个针对被佐证法定人数的持续 `H` 背离（ID-9a）。
  异常 gossip 是网络的免疫信号；客户端不得（MUST NOT）为了显得健康而压制它。

## 9. 与更新治理的合并接缝（OP-8 / 条目 4.1）

映射的根发布者与软件发布签名者看起来可能是同一套机制。**立场：在信任上保持它们
分离，即便它们共用工具。** 理由是它们有**相反的信任形态**：

- **ID-11（映射信任是复现，而非签名）。「[规范性]」** 映射之所以受信任，是因为它
  **从公开输入重建得出**（ID-5a）；它的正确性**不**系于*谁*发布了它。相比之下，一个
  发布二进制之所以受信任，是因为它**从公开源码重建得出**（可复现构建，roadmap
  4.1/4.2）—— 同样是复现，同样不是签名。所以那个*信任锚*是相同的 ——
  **可复现性，绝非作者身份** —— 并且项目必须（MUST）让二者都经由它。但**签名者/
  追加者集合必须（MUST）保持相异**：把映射日志的追加者绑定到发布签名者，会造出
  一份单一名册，其被攻陷会同时毒化*地理推断*与*软件*二者，即恰恰是条目 4.1 所要
  避免的那个被集中的胁迫目标。映射日志是无需许可的（ID-7）；发布流程可以有一个
  具名（化名）的签名者集合，它只*定位*一个它无法伪造的构建。把二者合并，是用映射的
  无需许可性去换发布流程的名册 —— 错误的方向。
- **ID-11a（共用工具没问题；共用权威不行）。** 二者都可以（MAY）重用同一套
  透明性日志构造（ID-6）与同一条 gossip 通道（GR-6）—— 共用*机制*不费分毫。它们
  不得（MUST NOT）共用的，是一组其签名对二者都承重的方，因为那组方会是 I-3 禁止的
  那个总开关（kill switch），如今还能同时扳动映射与代码。

## 10. 本部分未解决之事（已声明的残余）

本部分使两个诚实客户端可证明地取得一致、或可证明地检测到它们不同。它**并不**使
映射*为真*。「每个诚实客户端都认同的那个映射」与「中继物理上在哪里」之间的落差，
就是那个残余，而它是真实存在的：

- **藏在不相交前缀背后的同址在这里不可检测。** 一个在一个数据中心里运行中继、却
  公告着被公开 BGP/RIR 数据归于**不同** AS 的地址空间的对手，会被**正确的**映射
  标为不相交。没有任何对公开数据的可复现构建，能穿透一则看起来真实的 BGP 通告去看
  见其背后的机架。这一点被陈述在 roadmap 最深处那个坦诚之点中，并且它成立：
  **从覆盖网你所验证的，是针对一个有界信任数据集的一致性，而非真正的不相交性。**
  对于这种*被动*情形——一则正确的映射只是碰巧把同处一地的中继错误标注——该攻击是
  元数据/关联，因为诚实的映射不会使诚实池坍缩。（而*主动*情形，即一则被刻意选来使其
  坍缩的映射，更糟，并会触及内容：见 PS-12 及下方的内容操纵残余风险。）任务是去界定
  这个对手所获取的，而非假装它不存在。
- **BGP 在有些地方确实是有歧义的。** MOAS 前缀（一个前缀合法地由多个 AS 发源）、
  一个运营者名下的**兄弟 AS（sibling ASes）**（不同的 ASN，一个控制方 —— 映射看到
  两个 AS，而不相交现实是一个），以及 **anycast**（一个前缀，多个物理站点），都不是
  数据集的 bug；它们就是这片疆域本身。该映射保守地处理它们（ID-3a、ID-4b：
  MOAS → 集合，注册冲突 → `unknown`），这付出的代价是可用性（更多 `unknown` ⇒
  更多回退，PS-11）而非安全性。兄弟 AS 检测被明确地置于一个纯 BGP/RIR 构建的
  **范围之外**，并作为一个已声明的盲点留下：两个兄弟 AS 在它们并非不相交时被计作
  不相交。
- **司法辖区按决定保持粗粒度。** 国家级、从 RIR 派生的标签，是本部分所承诺的分辨率
  下界。更细的司法辖区推理（法律合作集团、司法互助的现实）被刻意**不**编码进去 ——
  那会是一个任何可复现构建都无法在不引入一个受信任意见的前提下做出的判断，而
  ID-1 禁止它。
- **一份敌意映射能够触及内容，而不只是元数据。** 上面那个同址残余是一次*被动*误差
  （正确的映射恰好标错了）。一份*被主动择定*的映射更糟：它能把按 AS 互不相交的选取
  操纵到 `≥ k` 条对手链路之上并攻破内容，而不只是关联（PS-12，它携带了防御）。本部分
  **并不**声称一份坏映射是仅元数据的；那个此前的声称是错的。该残余由 `k`/`n` 的余量、
  由 PS-12 的池塌缩防御、以及由重建（ID-5a）来界定 —— 而非由不可能性来界定。
- **复现（ID-5a）只在输入仍可取回之时才是仲裁者 —— 一个活性（liveness）界。** 只有
  当被钉定的公开输入仍能从某个诚实来源取回时，重建才能解决一场争议。RouteViews /
  RIPE RIS 的 MRT 转储与 RIR 委派文件**并非**对本项目有留存保证的永久归档；一旦一个
  被钉定的输入从每一个镜像中老化消失，`rebuild(manifest)` 便无法执行，而关于那个
  epoch 的争议便**没有仲裁者** —— 对那些恰恰需要它的旧 epoch 取证争议而言最为糟糕。
  一个合规的部署应当（SHOULD）把被钉定的输入字节托管（escrow）在一个内容寻址的
  存储里，并跨与映射相同的无需许可镜像集合复制，从而仲裁者继承映射自身的可用性；
  若无此举，ID-5a 被声明为**活性受界**，而非无条件的。（§4.1 尚未钉定的相关确定性
  隐患：镜像相关的裁剪使「≤ 边界的最后转储」变得镜像相关；RIR 每日单文件的突变
  对转储序列；以及跨解析器版本的 MRT *输入解码*背离，这是 ID-4d 的输出规范化所未
  覆盖的。）
- **ID-1 把权威重新安置到 OP-2；它并不消除信任。** 没有任何一方*签名*该映射
  （ID-1 在字面上成立，而对任何**重建**了的客户端而言，仅凭复现就扛得住）。但一个
  不重建的客户端（ID-5b 允许这样）依靠的是 gossip 法定人数的佐证（ID-7b、ID-9），
  其投票是无权威的**仅当** sybil/日蚀能被抵抗 —— 而那是 **OP-2，开放的**。在日蚀之下，
  含混其辞检测（ID-7a）无法触发（受害者碰不到任何诚实的根），一个由对手日志构成的
  法定人数能让一份坏映射看起来已被佐证，而且 —— 反方向、防御不足的那个方向 ——
  一个对手能让一份*好的*本地映射看起来*未被佐证*，并经由 ID-9a 的「把你的映射视作
  可疑、重新取回」把受害者逼下它（一次经由诚实机制自身实现的降级）。所以对不重建的
  或被日蚀的客户端而言，「没有权威」意味着「信任那个法定人数」，而那只在 OP-2 成立的
  限度内成立。本部分把映射权威问题**归约**到 OP-2；它并不消解它。

坦诚的总结：**该数据集的错误率是一个已声明的、非零的残余，而非一个要修到零的
缺陷** —— 并且，正如刚添加的三点所明示的，内容操纵的天花板（PS-12）、仲裁者上的
活性界、以及映射权威向 OP-2 的归约也同样如此。这些是拒绝一个权威的代价。正确的
应对不是隐藏它们，而是把它们界定住、把错误率喂给模拟器、并向用户展示所达到的水平
（PS-9、PS-11）。

## 11. 错误率喂给模拟器（不是挥手带过）

§10 的残余不是修辞上的；它恰恰是模拟器已经在消费的那个量。`poc/network_sim.py`
暴露了 **`infer_error`** —— 即客户端为一个中继所推断出的 AS 为**错**的概率（一半
时间是错的 AS，一半时间是 `unknown`），建模了一个既会误映射又有缺口的数据集
（network_sim.py，`Network.random`）。这里所指定的映射**就是**那个数据集，而其被
测得的残余**就是**那个旋钮：

- **ID-12（映射声明一个被测得的错误率）。「[规范性]」** 一个合规的映射发布必须
  （MUST）附带一个**被测得的错误估计** —— 即它针对独立公开地面真值样本的不一致率、
  以及它的 `unknown` 占比 —— 从公开数据可复现地推导得出，从而这个数字本身背后
  没有权威。那被测得的一对值（误映射率、`unknown` 率）是客户端喂给第 3 部分置信
  机制（roadmap 2.2）的值，也是模拟器作为 `infer_error` 扫掠的值。
- **ID-12a（零错误情形是最好情形，绝非预期情形）。** 依据 PS-11，模拟器的零错误、
  全视图数字是**最好**情形；一个合规的客户端必须（MUST）使用其**真实**映射所声明的
  错误来呈现所达到的不相交性水平（PS-9），并且 UI 不得（MUST NOT）把一个内容破坏
  数字援引为仿佛它也界定了关联性（PS-11）—— 那个让一个坏映射可被扛过去的不对称性
  （ID-8a），正是那个 UI 不得误报为安全性的不对称性。

## 12. 此处引入的需求

- **ID-1** —— 没有映射权威：只信任复现与哈希。
- **ID-2 / ID-2a** —— 产物形态（前缀 → AS，AS → 粗粒度司法辖区），由 `H` 内容寻址；
  查找是全的，`unknown` 是一等的。
- **ID-3 / ID-3a** —— 只用公开的、被钉定的输入（RouteViews + RIPE RIS BGP，五份
  RIR 委派文件）；多视点源解析，MOAS 保留为一个集合。
- **ID-4 / ID-4a–d** —— 确定性：UTC epoch 钉定转储时点、固定全序、被指定的破平局、
  没有浮动输入、规范容器 + 一个映射测试向量。
- **ID-5 / ID-5a / ID-5b** —— 一致即哈希相等；从输入重建是无权威的仲裁者；拒绝
  不可复现者。
- **ID-6 / ID-7 / ID-7a–c** —— 无需许可的、仅追加的、`(epoch, H, manifest-hash)` 的
  Merkle 透明性日志；含混其辞由 gossip 根 + 一致性证明逮到；多个日志，没有一个规范
  日志；日志持有承诺，而非映射。
- **ID-8 / ID-8a / ID-8b** —— bootstrap 是被声明的 TOFU；一个坏的第一映射的损害被
  界定，但**不是仅元数据的** —— 一份操纵地图能够触及内容（PS-12），所以那个界是
  有条件的（`k`/`n` 余量 + PS-12 防御 + 重建）、可检测的，且复现无法被伪造；检测，
  而非声称阻止。
- **ID-9 / ID-9a / ID-10** —— 在 GR-8 之下刷新与 gossip `(epoch, H)` 和根；背离经由
  PS-9 展示；对那三种攻击签名强制的异常 gossip。
- **ID-11 / ID-11a** —— 合并接缝：与发布治理相同的信任锚（可复现性），但**分离的**
  签名者/追加者集合；共用工具可以，共用权威不行。
- **ID-12 / ID-12a** —— 映射附带一个被测得的、可复现的错误估计，它喂给模拟器的
  `infer_error` 旋钮与第 3 部分的置信；零错误情形是最好情形，绝非预期情形。

ID-1 与 ID-5a 是承重的两条：没有权威，以及复现是仲裁者。二者都是有界的，而非绝对的
—— 对一个不重建的客户端而言 ID-1 归约到 OP-2，而 ID-5a 是活性受界的（§10）。本部分
最初提出的第三条声称 —— 即一个坏映射无法触及内容 —— 已被一次敌意评审**打破**：
一份操纵地图把对手机动到 `k` 之外并攻破内容，而不只是关联。本部分不去隐藏它，而是
如今公开地扛着它：防御是 PS-12，残余在 §10 中被声明。用同样的方式打破其余部分 ——
找出一个需要受信任方的步骤、一个无法从其输入重建的映射、一个我们漏掉的活性缺口，
或一条坏映射绕过 PS-12 防御而触及内容的*新*路径 —— 你便打破了本部分。那就是邀请，
而它已经被接受过一次。`poc/network_sim.py` 的 `infer_error` 扫掠（以及 PS-12 的操纵
构造）是 §11 背后那个可执行的 strawman；先攻击模型，再攻击这段文字。
