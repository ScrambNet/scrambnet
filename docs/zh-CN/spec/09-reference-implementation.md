# ScrambNet 规范 —— 第 9 部分：参考实现要求

> **非规范性翻译。** 规范版本以英文为准（[en](../../en/spec/09-reference-implementation.md)）。

**状态：草稿（DRAFT）。** 本部分以编号需求（`RI-n`）的形式陈述：一个真实节点
必须（MUST）做到、而概念验证（PoC）却刻意省略的那些事项——每一条规则都系于它
所应对的威胁，并在适用之处系于它所保护的不变量（I-1…I-4）。`poc/` 中的那个玩具是
一份*可执行的规范*，而非一个节点：它在自己的头几行里就声明了这一点（"NOT
PRODUCTION CODE. No constant-time arithmetic, no networking, no onion layer"）。
此处的一切，即是那个玩具与某个你敢指向一个敌意网络之物之间的距离。每一个数字都是
一个待按需求编号攻击的 strawman；更尖锐的邀请在 §1 中，而 §11 点明什么仍然悬而未决。

## 1. 核心张力：一个信息论下界，其无条件性恰好仅及于计算它的那段代码

ScrambNet 兜售一个**无条件的**内容下界（I-2，在第 7 部分中已证明）：在少于 `k`
份额的情况下，密文与秘密在*统计上独立*，面对无界计算与任意量子计算机皆然。那条
证明讲的是**值**——对手所持有的那些份额字节，不携带任何关于秘密的信息。它对
**一台真实机器如何计算出这些字节**只字未言，而下界恰恰是在那里、无需任何定理出错
就可能丢失。

一次以查表实现的 GF(2⁸) 乘法（PoC 的 `_EXP`/`_LOG` 表，`poc/dispersal.py`）会在一个
**取决于某个秘密份额字节**的地址处索引内存。在真实硬件上，缓存状态使该访问的耗时
对一个同驻对手可观测。因此，该查表经由一个时序侧信道，泄露了下界本要藏起的那些
字节本身。于是下界便*在理论上无条件、在实践中却可被恢复*。

这是本部分中最重要的一句话，作为一条原则陈述如下：

> **一个揭示秘密份额字节、系数或内容密钥的时序或内存泄露侧信道，并不是 I-2 获准
> 拥有的那种"计算型"攻破。它就是对 I-2 本身的攻破。** 第 7 部分恰好只许可一项
> 计算假设——那个凌驾于 `k` *之上*的端到端 AEAD（SP-1a）——此外别无其他。一个
> 泄露 `k` 以下秘密字节的侧信道，并不让对手付出"在某项假设之下的工作量"；它把
> 那些字节径直奉上。SA-1/SA-2 的证明假设对手**只**看见那 `k−1` 个份额值与公开
> 参数。一个侧信道添加了一份该证明从未授予的视野，而该证明并不涵盖它。

由此有两个推论，本部分余下内容将其规范化：

- 下界的**计算路径**——Shamir `split`、`reconstruct` 以及 Lagrange 插值中，施加于
  依赖秘密之数据的每一次 GF(2⁸) 运算——必须（MUST）是恒定时间（constant-time）的
  （RI-1）。这不是加固；它是 SA-1/SA-2 得以描述真实系统的那个条件，恰如 SA-3
  （系数随机性）之所是。
- 下界的**内存残留**——份额、系数、派生出的密钥——必须（MUST）不得存活到能从一次
  堆转储、一个交换文件或一个核心转储中被读出（RI-9）。一个在线路上是信息论的、
  却可从 `/proc` 恢复的下界，不是一个下界。

PoC 诚实地承认它两者都未做到：它是纯 Python 的查表、没有清零、正确却泄露，而它也
如此声明。本部分便是一个真实节点必须转而满足的那份清单。在 PoC *已经*强制施行某条
规则之处（它拒绝分散尚未经过 AEAD 的明文——`send()` 在拆分之前先 seal），那便是
基准线，而非一种讲究，并且 RI-6 把它提升为一项 MUST。

**范围。** 本部分约束的是别处已固定之构造的*实现*；它不引入任何新的线路格式，也不
改动线路上的任何字节（那会是一处 I-1/I-4 改动，归属于第 1–6 部分）。它不得（MUST
NOT）被解读为放松它所引用的任何需求；凡它看似如此之处，被引用的那一部分胜出，而该
矛盾是一处应报告的缺陷。

## 2. 恒定时间的域算术（下界的计算路径）

- **RI-1（恒定时间 GF(2⁸)，保护 I-2）。** 施加于依赖秘密之数据的所有 GF(2⁸) 算术
  ——Shamir `split`（对秘密系数与秘密常数项作多项式求值）、`reconstruct`/Lagrange
  插值（包括基底分母中的域**求逆** `gf_inv`），以及任何其操作数为一个份额字节、
  一个系数或一个已重构的秘密字节的乘法——必须（MUST）**在不含依赖秘密的分支、且不含
  依赖秘密的内存地址访问**的前提下计算。具体而言，一个实现不得（MUST NOT）在一个由
  秘密值导出的偏移处索引一个表（`_EXP`/`_LOG`、一个 S 盒，或任何数组）。合规的技术
  有：一次恒定时间的比特切片或塔域乘法、一次无进位乘法（`CLMUL`）约简，或一个由某个
  *记载*了这些运算的恒定时间行为的库所提供的域。威胁：一个同驻或远程时序对手从缓存
  或分支时序中恢复出秘密份额字节——这是一次对 I-2 的**直接攻破**（见 §1），而非
  计算型的攻破。这对**拆分与重构**对称地适用：一个执行重构的端点，会像一个拆分者
  泄露它正在分散的秘密那样，泄露它刚刚恢复出的秘密。
- **RI-1a（求逆与除法不予豁免）。** Lagrange 分母的逆（`poc/dispersal.py` 中的
  `gf_inv`，在那里被算作 `_EXP[255 − _LOG[a]]`）作用于一个由秘密份额集合导出的值，
  因此必须（MUST）是恒定时间的；一次数据依赖的求幂或一次查表求逆都是不合规的。一个
  实现应当（SHOULD）优先采用一种免求逆的插值（例如把各分母批处理，并经由 Fermat
  `a^{254}`、以一条固定加法链、或 Montgomery 技巧只求逆一次），从而不残留任何依赖
  秘密的除法。求值点 `x_1…x_n` 是**公开的**（第 7 部分 §2），因此*仅对它们本身*的
  算术无需是恒定时间的；一旦一个公开点被乘入某个秘密，该乘积便是秘密。
- **RI-1b（矢量并不认证时序）。** 通过路线图 3.2 的 GF 测试矢量，证明的是一次乘法是
  *正确的*，而非它是*恒定时间的*：PoC 那些泄露的表也通过同样的矢量。一个实现不得
  （MUST NOT）把矢量合规视作 RI-1 合规的证据。恒定时间行为应当（SHOULD）由一个时序
  分析或统计工具（例如 dudect 式的泄露测试）来检查，并且在平台允许之处，通过禁用那些
  会重新引入依赖秘密之分支的编译器变换来检查（RI-9b）。
- **RI-1c（秘密的整个生命期都是恒定时间的，而不仅是它的域运算，保护 I-2）。** 恒定
  时间纪律由**数据流定义，而非由点名那些 GF 运算定义**：任何被某个份额字节、某个
  系数或某个已重构秘密字节所沾染的值，都承袭 RI-1 的义务，直到它被清零（RI-9）为止，
  而该义务一直延伸到域层*之外*。尤其是，已重构秘密的长度前缀（SP-8）必须（MUST）被
  解析，而恢复出的明文必须被拷贝、切片与校验，**在不含依赖秘密之分支、且不含依赖
  秘密长度之内存访问**的前提下进行；`unpad` 不得（MUST NOT）以一种观察者可计时的
  方式在解码出的长度上分支，并且对一个秘密的任何比较、边界检查或缓冲区移动都不得
  是数据依赖的。威胁：§1 自身的那条原则——"一个执行重构的端点，会像一个拆分者泄露
  它正在分散的秘密那样，泄露它刚刚恢复出的秘密"——只有当对恢复出的秘密的*整个*处理
  都是恒定时间、而不仅是它的 GF 算术时，才会被强制施行。一个使用了一个经验证的恒定
  时间域（RI-1）和一个经审验的恒定时间 AEAD（RI-8），却随后在一个恢复出的长度上
  分支的节点，满足了其他每一条 MUST，却经由时序泄露了恢复出的秘密结构，而依据与
  RI-1 相同的论证，这是一次对 I-2 的直接攻破。

## 3. CSPRNG 纪律（下界恰好与它的随机性一样强）

下界不会强于 Shamir 系数的随机性：第 7 部分的 SA-3 是整份规范中"保证度最高的部件"，
而 `test_properties.test_coefficient_reuse_breaks_the_floor` 表明重用会确定无疑地
泄露秘密。同一份纪律支配着节点所抽取的每一个其他秘密。

- **RI-2（取自操作系统的密码学 DRBG，经由 SA-3 保护 I-2）。** 所有秘密随机性——Shamir
  系数（SA-3）、CH-3 的逐包链路一次性值 `x`、在非确定性之处的 `msg_nonce`/消息计数器、
  `kpair` 生成，以及任何 `box_id` 盐值——必须（MUST）由一个以操作系统 CSPRNG
  （`getrandom`/`getentropy`、池初始化之后的 `/dev/urandom`，或一个等效的阻塞直至
  已播种的源）播种的密码学安全 DRBG 产生。一个实现不得（MUST NOT）为本清单中的任何
  值使用一个非密码学的 PRNG（一个 LCG、Mersenne Twister、`rand()`、一个计数器之哈希，
  或一个被当作"随机"复用的流）。
- **RI-2a（fork 安全与 clone 安全——那场经典的灾难）。** 一个执行 `fork()`、从检查点
  被恢复、被迁移，或作为一个 VM 或容器镜像被克隆的进程，不得（MUST NOT）复用在分裂之前
  产出过输出的 DRBG 状态。实现必须（MUST）在 fork/恢复时从操作系统重新播种（例如一套
  `pthread_atfork`/`MADV_WIPEONFORK` 纪律，或一次逐调用的操作系统抽取），从而使任何
  两个进程都绝不发出相同的系数流或相同的一次性值 `x`。威胁：两个一模一样的 VM 克隆在
  **同一套系数**之下拆分*不同的*消息，于是依据 SA-3，这对份额集合变得与两个秘密都相关
  ——那场教科书式的随机性灾难，也是一次对 I-2 的直接攻破。之所以特别点出此项，是因为它
  对任何单进程测试都是不可见的。
- **RI-2b（健康检查与启动检查）。** 在发出第一个秘密值之前，一个节点必须（MUST）确认
  操作系统的熵源已播种（若池尚未就绪，它不得（MUST NOT）回退到一个低熵源），并且应当
  （SHOULD）对 DRBG 运行一次启动自检。一个节点应当（SHOULD）在它有访问权之处，对原始
  熵执行一次持续的重复/卡死输出检测，并且必须（MUST）fail closed——拒绝拆分或拒绝构建
  一个数据包——而非带着一个可疑的生成器继续前进。一个无法被验证的生成器被视作已损坏。
- **RI-2c（生产中无可注入的系数——但合规矢量仍要运行）。** PoC 的 `split(..., coeffs=...)`
  参数之所以存在，只是为了让矢量可以确定、并让重用攻破得以演示。一个生产制品不得（MUST
  NOT）暴露任何路径——标志、配置、环境变量或符号——让一个调用者得以提供、记录或钉定
  Shamir 系数或一次性值 `x`；这样一条路径是一处 SA-3 的脚枪。与路线图 3.2 合规矢量
  （RI-10）——它们需要被注入的确定性系数才能复现——的调和，是一道**构建期测试门**：该
  注入路径可以（MAY）*仅*存在于一道**不见于任何生产制品**、且在生产中运行期不可达的门
  之后。矢量是对照一个启用了该门的测试构建来匹配的；生产构建必须（MUST）与之一模一样，
  只除去那段被设门的代码之缺席，而该等价性应当（SHOULD）由构建来验证（例如对两者作一次
  可复现的 diff）。"被编译掉，而非仅仅被劝阻"所指的恰是此意：为测试二进制而存在，却从
  所交付的那个之中物理地缺席——绝不是一个运行期开关。

## 4. nonce 与跨重启的密钥轮换状态

两个不同的秘密绝不可以跨一次重启而被复用：AEAD/tag 的 nonce（SP-7b）与中继的 `onion`
静态纪元（CH-5）。一次重启，正是一个节点最受诱惑去"从头开始"并复用一个它已经用过之值的
时刻。

- **RI-3（单调的 nonce 高水位标记跨重启存续，保护 SP-7b 与 SP-1a）。** 逐 `kpair`，
  发送者的 `msg_nonce`（一个严格递增的消息计数器，SP-7b）必须（MUST）被持久化，并且
  不得（MUST NOT）跨一次重启、崩溃或时钟改变而回滚。实现必须（MUST）在**它所覆盖的
  那个 nonce 被用到线路上之前**，把该高水位标记 `fsync`（或平台等价的持久化屏障）**到
  稳定存储**，从而使一次介于使用与持久化之间的崩溃只能*跳过* nonce，绝不重复它们。一个
  节点不得（MUST NOT）在同一个 `kpair` 之下复用或减小一个 `msg_nonce`。威胁：一个被
  复用的 `msg_nonce` 是**双重致命的**（SP-7b）——它使 SP-7 的 tag 碰撞（令某个份额集合
  跨串通的丢包节点可关联）**而且**，由于 `msg_nonce` 即为 ChaCha20-Poly1305 的 nonce
  （SP-1a），它以一次 two-time pad 摧毁 AEAD 机密性。在一次被恢复的备份之后把计数器
  回滚，才是那个现实的失败，而它是一次机密性攻破，而非一个小故障。
- **RI-3a（预留以界定 fsync 开销）。** 一个实现可以（MAY）以块为单位持久化高水位标记
  （以一次持久写预留 `B` 个 nonce，从内存中发放它们，在块耗尽之前再次持久化），以避免
  逐消息一次 fsync。一次崩溃至多浪费一个块中未用的尾部——这是可接受的，因为计数器空间
  很大，而跳过是安全的、重复却是致命的。在任何崩溃恢复路径下，它都不得（MUST NOT）发放
  一个处于或低于最后一次持久持久化之标记的 nonce。
- **RI-3b（一次恢复不是一次重启——检测回滚或退役该密钥，保护 SP-7b/SP-1a）。**
  RI-3/RI-3a 防御的是一次*崩溃*（被持久化的标记只会向前移动）；它们**并不**防御一次把
  被持久化的标记本身倒回的 VM 快照、文件系统快照或备份**恢复**——正是 RI-3 点名为那个
  现实失败的"在一次被恢复的备份之后把计数器回滚"。一个节点不得（MUST NOT）假定其被
  持久化的 nonce 存储跨这样一次恢复是单调的。因此它必须（MUST）要么（a）把高水位标记
  绑定到一个逐引导/逐恢复的 nonce **盐值**（或一个单调的世代计数器），且该盐值与预留
  在*同一次持久写*中被持久化，从而使一个被倒回的存储可被检测，并在检测到时**退役该
  `kpair`**——派生出一把全新的内容/tag 密钥，把一个被倒回计数器之下被复用的盐值视作
  一次失陷——要么（b）在任何一个恢复的迹象上（系统时钟倒退，或被持久化的世代计数器
  减小）拒绝在受影响的 `kpair` 之下发出，直到一把全新的 `kpair` 被带外协商出来（第 6
  部分）。预留（RI-3a）必须（MUST）在预留的持久写中携带该世代计数器，从而使一次恢复
  不能在不被检测的情况下重放一整个被预留的块。威胁：没有这一点，一次快照恢复会重新发出
  一整个块的已用 `msg_nonce` 值——即 RI-3 那个双重致命的 two-time pad，位于 RI-3a 的
  仅崩溃守卫看不见的一条路径上。
- **RI-4（onion 静态纪元状态与安全退役，保护 CH-5/CH-6）。** 一个中继必须（MUST）
  持久化它处于哪一个 `onion` 静态纪元（活跃的私钥、它的 `created`/`expiry`，以及在途
  宽限窗口），从而使一次重启不会静默地重新发布一把过期密钥、复活一把已退役的密钥，或在
  同一个已声明的纪元之内铸造第二把"全新的"静态密钥。在轮换时（≤7 天，CH-5），该中继
  必须（MUST）在在途宽限期过去之后，**清零那把已退役静态密钥的私有一半**（RI-9），并
  不得（MUST NOT）保留它；一个保留旧静态密钥的中继，是在扩大它自身的 CH-6 可关联性
  暴露窗，并且不合规。客户端仍由 GR-4/CH-5 约束去拒绝任何其 `expiry` 超过 `created + 7
  days`（GR-2 的密钥 6）的记录，从而使一个忘记了自己纪元的节点无法通过重新发布来延长
  该窗口。威胁：一次把静态密钥倒回客户端已经见过之窗口的重启，或一次未能销毁一把已退役
  静态密钥的重启，重新打开了轮换上限本为界定而存在的那处 CH-5a 可关联性暴露。

## 5. 重放缓存的持久化

ScrambNet 在两层拒绝重放，且两者都是有状态的：链路层按密钥纪元丢弃一个已见的 `gamma`
（SP-5），而存储层丢弃对一个已存储 `(box_id, slot)` 的再次投递（SP-7b，RZ-7）。一次
忘记此状态的重启重新打开一个重放窗口。

- **RI-5（重放状态跨重启存续，界定于纪元，保护 SP-5 / SP-7b）。** 一个中继必须（MUST）
  持久化、或安全且完整地重建它**对当前密钥纪元的**已见 `gamma` 值的 Sphinx 重放缓存，
  而一个丢包节点必须（MUST）持久化它那套已存储的 `(box_id, slot)` 投递，从而使一次重启
  或崩溃不会接受一个它在活跃纪元之内已经见过的数据包或投递。威胁：一个带着空重放缓存
  重启的中继，会把一个对手在纪元之内捕获并重新注入的每一个数据包重新纳入——一个被重新
  打开的重放窗口，它在丢包层还能对照 RZ-7 的逐 box 上限使诚实邮件成倍增加或被挤出。
- **RI-5a（该缓存被界定——由两个*不同的*保留窗口界定，而非"那个纪元"）。** 这两份重放
  缓存各自在内存中被界定，但由一个实现不得（MUST NOT）混淆的**互不相同的**窗口界定：
    - Sphinx 的 `gamma` 缓存由**洋葱静态密钥纪元**（CH-5，≤7 天）界定——一个 `gamma`
      只在为它生成密钥的那把密钥仍活跃时才可被重放；
    - `(box_id, slot)` 的投递去重集合由**槽过期**（RZ-7，7 天）界定，**而非**由 1 天的
      `box_id` 轮换（RZ-10）界定。box id 为了*寻址*而每日轮换，但一个被投递的槽会被
      *存储*至多 7 天（加上 RZ-14 的边界宽限），因此只要一次再次投递会撞上的那个槽仍能
      被存储，它便可被丢弃——至多约 7 个 box 纪元。把这个集合按一天来定尺寸，会使它约
      小 7×。
  一个实现必须（MUST）在每份缓存自身的窗口过去之后丢弃其状态（`gamma` 缓存在密钥纪元
  末，投递集合在槽过期时），从而把内存分别封顶于约为该密钥纪元之数据包量与 7 天之投递量。
  它可以（MAY）用一个计数结构（例如一个定尺寸的 Bloom/cuckoo 过滤器）进一步界定内存，
  **只要**它被调校到使假阳性保持在一个运营上可忽略的比率之下；一次假阳性丢弃一个诚实
  数据包（一次自残式 DoS），一次假阴性放入一次重放（一次安全失败），因此该结构必须
  （MUST）被定尺寸到：在其保留窗口之内使后者不可能、并使前者罕见。一个无法持久化一份
  缓存的节点，必须（MUST）为它无法覆盖的一个窗口 fail closed（把那段被遗忘的跨度视作
  可被重放，并且对 `gamma` 缓存而言，轮换密钥纪元），而非静默地接受重放。
- **RI-5b（重建必须完整，否则被当作一次轮换——而一次恢复不是一次重建）。** 一个在崩溃
  之后重建重放状态（而非持续持久化它）的实现，必须（MUST）要么为活跃窗口完整地重构它，
  要么把这段缺口当作一个新密钥纪元的开端（新密钥，于是旧的 `gamma` 值不再可被接受）。
  一次把窗口的一部分留作未保护的部分重建，是不合规的。此外，一次把缓存倒回一个*更早的、
  看似完整的*状态的 VM/文件系统**恢复**不是一次崩溃，而 RI-5b 的完整性检查无法检测它：
  一个被恢复的中继带着一份来自*早于*对手所捕获数据包的缓存回来，并把它们重新纳入。一个
  节点必须（MUST）把任何一个恢复的迹象（与 RI-3b 相同的时钟倒退或世代计数器减小）当作
  一次强制的**密钥纪元轮换**，从而使恢复前的 `gamma` 值不再可被接受，无论那份被倒回的
  缓存里有什么。

## 6. 抗误用的 API（让不安全之事成为不可能）

I-1 与 `[soundness]` 纪律要求 API 让那个不安全的操作*不可表示*，而非仅仅被记载为不明智。
SP-1 的次序（先加密**然后**拆分）与 SP-7a 的 fail-closed 规则，是一个 API 最容易倒置的
两处。

- **RI-6（API 必须拒绝无 AEAD 的明文，保护 SP-1/SP-1a）。** 分散入口必须（MUST）拒绝
  任何尚未经过端到端 AEAD（SP-1a）的输入：它**只**分散密文，绝不分散明文。不得（MUST
  NOT）存在一条绕过 SP-1 之先加密后拆分次序的公开"拆分这些原始字节"路径——即不存在任何
  方式在不把 AEAD seal 置于其前的情况下抵达 `split()`。PoC 已经满足这条基准线：`send()`
  在 `disperse` 之前调用 `e2e.seal`，而 `dispersal.py` 被记载为"从不触碰明文"。一个真实
  节点必须（MUST）在类型层面让那扇门保持关闭，而非靠约定。威胁：直接拆分明文摧毁那条
  *计算型护带*（第 7 部分的第 2 层）——于是对任何 `≥k` 的对手而言，份额径直重构为明文，
  其后并无 AEAD——并倒置了整个设计所倚赖的那个组合。
- **RI-6a（在类型上把密文与明文分离）。** 一个实现应当（SHOULD）把"明文"与"端到端密文"
  表示为互不相同、不可互换的类型，从而使 SP-1 的次序不能因传入错误的缓冲区而被倒置，并
  使一次"拆分原始字节"的调用成为一个编译期错误而非一个运行期检查。在语言无法强制施行
  此点之处，节点必须（MUST）插入一个默认开启、且不能被配置禁用的运行期守卫。
- **RI-6b（原始域入口必须是模块私有的）。** 类型分离（RI-6a）单凭自身还不够：原始的
  `split`/`reconstruct` 以及任何直接的域入口必须（MUST）是模块私有的（不导出），从而使
  *唯一*的公开分散符号是那个接受 AEAD 密文类型者（RI-6）与那个返回一个经认证的 open
  结果者（RI-7）。一个公开的 `split(raw_bytes)` 或 `reconstruct(...)` 符号本身就是那处
  缺陷，与一个调用者传给它什么无关——在一个 `bytes` 即 `bytes` 的语言里，一个被导出的
  原始拆分让一个更低层的调用者在类型检查干净利落的同时绕过 AEAD 门。PoC 在模块作用域
  暴露这些，*是因为它是一份可执行规范*；一个真实节点不得（MUST NOT）如此。
- **RI-7（重构必须 fail closed，且以恒定时间进行，保护 SP-7a）。** AEAD 的 tag 是**唯一**
  的完整性裁决者（SP-7a）：Shamir 重构自身毫无完整性可言，因此一个被翻转的份额字节或一个
  被谎报的 `(k,n)`，会产出一个自洽但错误的候选，唯有 AEAD 拒绝它。重构 API 必须（MUST）
  **仅**在端到端 AEAD 验证通过之后才返回一条消息，并且必须（MUST）丢弃——绝不呈现、记录
  或据以行事——任何其 tag 失败的候选。它不得（MUST NOT）向应用代码暴露一个"未认证重构"
  的结果。**该 fail-closed 丢弃还必须相对于它*为何*失败是恒定时间的：** 重构—然后—open
  的路径必须（MUST）耗费不可区分的时间，并发出不可区分的响应（CH-9/I-4），无论 AEAD 的
  tag 验证通过了、`(k,n)` 字节被谎报了（RI-7a），还是份额字节被破坏了——一个能喂入重构
  候选的对手（SP-7a 的敌意丢包残余，或一个 `≥k` 联盟重放份额集合）不得（MUST NOT）经由
  时序或经由响应得知是哪一种，否则那条拒绝路径便成为一个填充预言机式的区分器，哪怕 tag
  *比较*（RI-8）是恒定时间的。PoC 钉住了这个 fail-closed 行为（`receive()` 在来自
  `e2e.open_` 的 `ValueError` 上丢弃，`test_tampered_share_fails_closed`）；一个真实节点
  必须（MUST）不在它周围添加一条路径，也不穿过它添加一道时序旁门。威胁：递上一个未认证
  的重构，把被接受的 SP-7a 拒绝服务残余变成对攻击者所择垃圾的递送；对拒绝计时，把它变成
  一个预言机。
- **RI-7a（防御性地解析 `params` 字节，不要信任它）。** 在一个敌意份额上，`(k,n)` 字节是
  攻击者控制的（SP-7a），且其 nibble 顺序被矢量锁定（SP-7a / 路线图 3.2）。一个实现必须
  （MUST）在使用之前，对照矢量锁定的顺序、并对照 `1 ≤ k ≤ n ≤ 15`（如 `_check_params`
  所为）校验它，并且必须（MUST）把一次在被谎报 `(k,n)` 之下的重构当作一次寻常的
  fail-closed 丢弃（RI-7），绝不当作分配无界内存或越界索引的理由。

## 7. AEAD 与 tag 比较（护带也必须是恒定时间的）

那条计算型护带（第 2 层，第 7 部分 §5）的可靠程度，恰好仅及于它的实现。PoC 的 AEAD
对照 RFC 8439 是正确的，但明确地**不是**恒定时间的（"它是正确的……但经由时序泄露，
因此一个真实节点必须使用一个经审验的恒定时间库"）。

- **RI-8（恒定时间的 AEAD 与 tag 比较，保护 SP-1a / SP-7）。** 一个节点必须（MUST）
  使用一个其数据路径与其**认证标签比较**皆为恒定时间的 ChaCha20-Poly1305 实现，并且
  必须（MUST）以一个恒定时间的相等原语（无提前退出的 `memcmp`，无在 tag 字节上的数据
  依赖分支）比较 SP-7 的份额 tag 与 SP-7a 的 AEAD tag。威胁：一次非恒定时间的 tag 检查
  是一个经典的伪造预言机——对该比较作逐字节计时，让一个对手伪造出一个有效的 tag——它直接
  攻击护带（SP-1a）与份额识别 tag（SP-7）。Poly1305 与 X25519 的算术同样必须（MUST）是
  恒定时间的（RI-11）；二者中任一者的变时实现都经由时序泄露密钥材料。

## 8. 那个玩具省略的洋葱层

PoC 有"no onion layer"：`dispersal.py` 只作用于 `delta` 载荷的份额，而 Sphinx 头部
（`alpha`/`beta`/`gamma`）及其逐跳密码学只作为第 1 部分 §5 的规范而存在。一个真实节点
必须（MUST）实现那一层，并且它的密码学在此处于范围之内，因为它在与下界相同的侧信道威胁
之下，携带着秘密材料（跳秘密与客户端一次性值）。

- **RI-10（实现 CH-2 的逐跳派生，保护 I-1/I-4）。** 一个节点必须（MUST）一丝不差地实现
  第 1 部分 §5 的 Sphinx 链路握手：逐跳，从盲化的群元素与中继静态密钥派生出共享秘密
  `s_i = X25519(alpha_i, onion_i)`（CH-2），并由 `s_i` 经 HKDF-BLAKE2s 在固定标签
  `sphinx-rho`、`sphinx-mu`、`sphinx-delta` 之下派生出路由信息流密钥、`gamma` MAC 密钥
  与 `delta` AEAD 密钥（CH-2；确切的标签字节与链接在路线图 3.2 下被矢量锁定）。它必须
  （MUST）执行 Sphinx 盲化（逐跳重新随机化 `alpha`）并强制施行 SP-5 的抗重放纪律。
  **不存在单独的握手 transcript**（CH-1）；一个在一条链路上发出或期待任何 Noise/握手
  消息的节点是不合规的（CH-1）。*提醒：* 这一派生的跨实现测试矢量是路线图 3.2，并且必须
  （MUST）在其发布之后被匹配；在此之前，两个实现尚未被证明在这一层互操作（I-1），而此点
  被公开陈述，而非被假定。
- **RI-11（恒定时间的 X25519 与无密钥—一次性纪律，保护 CH-3/CH-6/I-2）。** 每一跳上的
  X25519 标量乘法必须（MUST）是恒定时间的（一个无依赖秘密之分支或内存访问的
  Montgomery 梯实现）；一个变时的 X25519 泄露跳标量、从而泄露跳秘密。`alpha_0` 背后的
  逐包客户端一次性标量 `x`（CH-3）必须（MUST）逐包从 CSPRNG（RI-2）全新采样，必须
  （MUST）绝不跨数据包复用，并且必须（MUST）在数据包被构建之后立即被清零（RI-9）——它的
  销毁正是使 CH-6 的纪元粒度前向保密成真之所在（一个被保留的 `x` 让一次日后的中继静态
  夺取重算出该设计承诺已消失的跳秘密）。一个中继同样必须（MUST）把它的 `onion` 静态密钥
  置于 RI-2 的密钥处理与 RI-4 的轮换/退役之下，并以恒定时间用它计算。
- **RI-11a（拒绝退化的共享秘密，以 X25519 正确的方式）。** X25519 刻意不暴露任何廉价的
  在曲线上/阶检验（RFC 7748），因此"校验 `alpha` 点"不是那个可构建的检查；所要求的、
  可构建的那个是：计算 `s_i = X25519(alpha_i, onion_i)`，并**以恒定时间，若所得共享秘密
  全为零则拒绝**（那个低阶 / 小子群的结果），在由它派生任何跳密钥*之前*。这否决了一个
  恶意前驱一个被强加的小阶或已知密钥的跳。由于线路上的每一个字节都是均匀的（SP-4/I-4），
  该检查是对*所计算出的秘密*的，而非对一个明文标志的，并且一个中继必须（MUST）在时间与
  字节上**与一次寻常的抗重放丢弃不可区分**地处理一个被拒绝的 `alpha`（SP-5/CH-9/I-4）
  ——无可区分的响应，无时序泄露。完整的点校验/编码规则在路线图 3.2 下被矢量锁定，但那个
  全零输出拒绝在*此处*即是规范性的，从而使该需求无需等待那份文件便可构建（I-1）。

## 9. 内存清零、交换与故障安全

一个在线路上无条件、却可从一次堆转储、一个交换文件或一个核心转储中恢复的下界，不是一个
下界（§1）。内存泄露揭示 I-2 所保护的那些 `k` 以下字节本身，因此清零是一项 I-2 需求，
而非卫生讲究。

- **RI-9（把秘密保存在可清零的存储中，并在使用后擦除它们，保护 I-2）。** Shamir 份额、
  多项式系数、重构出的秘密、每一把派生出的密钥（`content_key`、SP-7 的 `tag` 密钥、
  `box_id` 密钥、每一个 Sphinx 跳密钥 `s_i` 及其衍生物）、预共享的 `kpair`、客户端一次性
  值 `x`（RI-11），以及中继的 `onion` 静态密钥（RI-4），都必须（MUST）被保存在节点能够
  就地覆写的存储中，并且必须（MUST）一旦它们不再被需要就立即被清零。该义务之所以被陈述为
  *先作存储选择*，是因为一个光秃秃的"清零"在本规范自己的某些目标语言中是**物理上不可能
  的**：在 CPython（参考 PoC 的语言）中，一个处于不可变 `bytes` 对象里的秘密可能被
  interned、被分配器拷贝，并在没有任何可达覆写的情况下被释放，而一个拷贝/压缩式 GC
  （Go、Java……）可能迁移一个秘密，使得没有单次擦除能触及每一份拷贝。因此：
    - 在一个提供**确定性、就地可变**秘密存储的运行时中，节点必须（MUST）以一个编译器
      无法作为死存储消除的原语清零（`explicit_bzero`/`memset_s`/`SecureZeroMemory`/一道
      `volatile` 屏障，或该语言经审计的 `Zeroize`）——对一个将被释放的缓冲区作一次朴素的
      `memset` 是惯常地被优化掉的。
    - 在语言**无法**保证那一点之处（不可变字节串、一个拷贝/压缩式 GC、按值拷贝语义），
      节点必须（MUST）把每一个秘密保存在它*能够*清零的**锁定/本机/堆外**内存中（RI-9b
      的本机内存条款此时是一项 **MUST**，而非一项 SHOULD），并且必须（MUST）根本不把
      秘密保存在一个运行时托管的对象里（一个 `bytes`/`str`、一个 GC 堆数组）。
  该需求因此是"使用可清零的存储，然后擦除它"——在每一种语言中都可满足——而非"擦除一个
  运行时不让你触及的对象"。威胁：这些恰是下界所藏的 `k` 以下秘密字节；把它们留在被释放
  的堆、一个被复用的缓冲区、一份被迁移的 GC 拷贝，或一个被记录的结构里，让一次日后的
  内存读取把它们重构出来，而那是一次经由内存泄露的 I-2 攻破。
- **RI-9a（让秘密远离交换与核心转储）。** 秘密缓冲区应当（SHOULD）被锁定进 RAM
  （`mlock`/`mlockall`/`VirtualLock`），使它们绝不被换页到一个持久的交换文件，而该进程
  应当（SHOULD）禁用核心转储（`RLIMIT_CORE = 0` 或平台等价物）或把秘密页从其中排除。
  一个无法阻止秘密页被换出的节点应当（SHOULD）采用一种加密交换的部署，并且必须（MUST）
  记载该残余。威胁：一个交换文件或一个崩溃转储是那些 `k` 以下字节的一份持久的、驻留于
  磁盘的拷贝——即那个下界，溢出到了一处远比该进程更长久的存储。
- **RI-9b（挫败优化器与语言的危害）。** 一个实现必须（MUST）确保编译器与语言运行时不会
  重新引入这些规则所禁止的泄露：没有被优化复活的依赖秘密之分支（RI-1），没有来自一个
  重分配容器、一个被移动的值、一个被垃圾回收或拷贝式 GC 堆、字符串 interning，或一个
  捕获了某个秘密缓冲区的异常/栈回溯的被拷贝—并遗忘的秘密。在一个缓冲区可能被运行时拷贝的
  托管内存语言中，一个节点应当（SHOULD）把秘密保存在它能确定性清零的锁定/本机内存中，并且
  不得（MUST NOT）倚赖垃圾回收器去擦除它们。
- **RI-12（故障与异常安全——没有部分的或可关联的制品，保护 I-2/I-4）。** 一次*拆分中途*
  的崩溃、异常或取消，不得（MUST NOT）发出一个部分的份额集合、线路上的一个份额子集，或
  任何把一条消息的各份额关联起来的制品，并且不得（MUST NOT）留下未清零的秘密状态。一个
  实现必须（MUST）构建全部 `n` 份份额，并把发出作为一个相对于失败的全有或全无步骤来承诺，
  在任何错误路径上于回退之前清零系数与份额。威胁：一个在发出一些但并非全部份额之后崩溃、
  或在一个栈回溯里记录了一份中间份额的发送者，把一个相关的子集递给一个观察者（削弱 SP-7
  的不可关联性，并且若它揭示某条消息的 `≥k` 份，则削弱下界）——而一次未清零的回退把秘密
  留在了内存中（RI-9）。故障处理必须（MUST）fail closed：在拆分、分散或重构期间的任何
  错误上，产出无一物并擦除，而非产出某个部分之物。

## 10. 这些需求如何映射到不变量与威胁

| `RI` | 保护 | 它所否决的威胁（真实节点的攻击） |
|---|---|---|
| RI-1 / 1a / 1b / 1c | I-2 | 缓存/分支时序对 `k` 以下字节的恢复，含域运算之外对恢复出之秘密的处理 |
| RI-2 / 2a / 2b / 2c | I-2（SA-3） | 弱的/已 fork 的/可克隆的 RNG → 相关的系数 |
| RI-3 / 3a / 3b | SP-7b, SP-1a | 重启**或快照/备份恢复**时的 nonce 回滚 → tag 碰撞 + two-time pad |
| RI-4 | CH-5 / CH-6 | 静态纪元回滚或保留了的已退役静态密钥 |
| RI-5 / 5a / 5b | SP-5, SP-7b | 被遗忘的（或被恢复倒回的）重放状态重新打开重放窗口；两份缓存有不同的保留窗口 |
| RI-6 / 6a / 6b | SP-1 / SP-1a | 先拆分后加密摧毁计算型护带；一个公开的原始拆分符号绕过那道门 |
| RI-7 / 7a | SP-7a | 未认证**或时序可区分**的重构递送垃圾 / 变成一个预言机 |
| RI-8 | SP-1a, SP-7 | 非恒定时间的 tag 检查 → 伪造预言机 |
| RI-10 | I-1, I-4 | 那个未实现的洋葱层，以可互操作的方式构建 |
| RI-11 / 11a | CH-3 / CH-6, I-2 | 变时的 X25519 或一个被复用/被保留的一次性值 |
| RI-9 / 9a / 9b | I-2 | 对 `k` 以下字节的堆/交换/核心转储泄露 |
| RI-12 | I-2, I-4 | 部分的/可关联的制品或未清零的崩溃回退 |

那条贯穿线：一切触碰某个 `k` 以下秘密值（份额、系数、重构出的字节、内容密钥、跳秘密、
客户端一次性值）之物，都被持守到下界自身的标准——以恒定时间计算它（RI-1/8/11）、从一个
可靠、fork 安全的 CSPRNG 生成它（RI-2）、不跨一次重启持久化任何可复用的秘密
（RI-3/4/5）、绝不让 API 跳过 AEAD（RI-6/7），并在它能被读回之前擦除它（RI-9/12）。
一个审阅者攻破本部分的方式，是找到一条真实节点路径，在其上这样一个值被以变时计算、取自
一个被复用的流、跨一次重启被重复、未经认证被呈现，或被留作内存中可读——而那条路径随即是
一次 I-2 攻破，而非一个单纯的加固缺口。

## 11. 本部分**不**作决定之事

- **网络、传输与流量整形。** 变色龙传输（第 4 部分）、批量/混合策略与抖动（SP-6/OP-5），
  以及份额发出时序（SP-9/OP-4），在此处于范围之外；本部分约束的是*密码学*实现，而非
  调度器。份额之间的时序关联残余仍是 OP-4，未被任何 RI-n 处理（SA-2 与本部分讲的是值，
  而非发出时刻）。
- **路径选择与不相交性。** 校验 `n` 条份额路径不共享一个 AS 或司法管辖区（OP-1，第 3
  部分）不是一个原语实现的问题，在此不作要求；RI-7a 只守卫着不去*信任*一个被谎报的
  `(k,n)`，而非守卫着一个非不相交的路径集合。
- **女巫/eclipse 与 gossip 层。** 一个合规节点的正确密码学，并不凭自身抵抗一个财力雄厚、
  买下位置的对手（OP-2，GR-20a）；那个残余栖身于第 2 部分，不被本部分触碰。
- **重放结构的确切定尺寸与 fork 检测机制。** RI-5a 把重放缓存界定于纪元，并禁止一个易
  假阴性的过滤器，但那个具体的数据结构、它的参数，以及持久化介质，是实现选择，要对照
  路线图 3.2 的矢量与部署的数据包量来钉定，而非在此固定。
- **测试矢量与合规。** 那些认证两个实现互操作的矢量——作为规范性的 GF 表、Sphinx 逐跳
  派生、加密→拆分→存入→轮询→重构→解密的路径——是**路线图 3.2**，并被引用（RI-1b、
  RI-7a、RI-10、RI-11a），但在此不被复现。RI-1b 明言那些矢量认证正确性、绝不认证时序；
  一个侧信道测试套件是一项单独的、被推荐的义务（RI-1b），本部分要求它却不规定它。
- **后量子原语替换。** 套件 `0x02`（一个 PQ 跳 KEM，第 1 部分 §5 的收尾）改变的是 RI-11
  所约束的原语，而非它必须是恒定时间的那条需求；I-2 下界无论如何都是后量子安全的
  （SP-1a），因此此处无一物受阻于它。

## 12. 此处引入的需求

- **RI-1 / RI-1a / RI-1b / RI-1c** —— 恒定时间的 GF(2⁸) 乘法、求逆与除法，**扩展到恢复出
  之秘密的整个生命期**（SP-8 的长度解析与对一个重构出之字节的所有处理），而不仅是域运算；
  矢量认证正确性，而非时序。**[protects I-2]**
- **RI-2 / RI-2a / RI-2b / RI-2c** —— CSPRNG 纪律：取自操作系统的密码学 DRBG、fork/clone
  安全、健康检查、无可注入的系数（被设门于测试，不被交付）。**[protects I-2 via SA-3]**
- **RI-3 / RI-3a / RI-3b** —— 被持久化的、不回滚的 `msg_nonce` 高水位标记，使用前 fsync，
  **且一次恢复/快照被当作回滚**（检测或退役该 `kpair`）。**[protects SP-7b / SP-1a]**
- **RI-4** —— 被持久化的 `onion` 静态纪元状态与清零式退役。**[protects CH-5 / CH-6]**
- **RI-5 / RI-5a / RI-5b** —— 为 `gamma`（由密钥纪元界定）与 `(box_id, slot)`（由
  **7 天的槽过期**界定，而非 1 天的 box 轮换）而持久化的重放状态；一次把缓存倒回的恢复
  是一次强制的密钥纪元轮换。**[protects SP-5 / SP-7b]**
- **RI-6 / RI-6a / RI-6b** —— API 拒绝无 AEAD 的明文；在类型上分离密文；原始的
  `split`/`reconstruct` 是模块私有的。**[protects SP-1 / SP-1a]**
- **RI-7 / RI-7a** —— fail-closed **且恒定时间拒绝**的重构；防御性的 `(k,n)` 解析。
  **[protects SP-7a]**
- **RI-8** —— 恒定时间的 AEAD 与恒定时间的 tag 比较。**[protects SP-1a / SP-7]**
- **RI-9 / RI-9a / RI-9b** —— 先作可清零的存储（在运行时禁止就地擦除之处采用锁定/本机
  内存），然后作反死存储的清零；无交换、无核心转储；优化器/GC 危害。**[protects I-2]**
- **RI-10** —— 实现 CH-2 的 Sphinx 逐跳派生与抗重放/盲化纪律；矢量是路线图 3.2。
  **[protects I-1 / I-4]**
- **RI-11 / RI-11a** —— 恒定时间的 X25519；无密钥、逐包、已清零的一次性值；以恒定时间
  拒绝全零共享秘密。**[protects CH-3 / CH-6 / I-2]**
- **RI-12** —— 故障/异常安全：没有部分的或可关联的制品，在回退时清零，fail closed。
  **[protects I-2 / I-4]**

这些之中无一是一个定理；每一个都是这样一个条件：在其之下，第 7 部分的那些定理与第 1–6
部分的那些保证所描述的是一个**真实节点**，而非那个玩具。那个玩具刻意省略了它们之中的每
一个，并且如此声明。攻破本部分的方式，是指出一条真实节点代码路径，在其上一个 `k` 以下
秘密以一种上面没有任何 RI-n 禁止的方式被计算、被存储或被泄露——那条路径是一个在实践中
被攻破的下界，而找到它正是那份邀请。
