# ScrambNet 规范 —— 第 6 部分：会合与投递

> **非规范性翻译。** 规范版本以英文为准（[en](../../en/spec/06-rendezvous.md)）。

**状态：草稿（DRAFT）。** strawman 取值以 `(s)` 标记。本部分所开启的取回元数据与
经济学问题即 OP-9，且刻意悬而未决。

## 1. 范围

一条消息如何抵达某个不在——且绝不可在——任何人地图上的人。
接收者没有网络位置；他们拥有**联系卡**与
**死信箱**。发送者存入份额；接收者从自己的链路之后
取回它们。从来没有人向一个人*投递*。

## 2. 没有人就人做 gossip

- **RZ-1.** 一个接收者不得（MUST NOT）通过 gossip 变得可被发现。只有中继
  发布记录（第 2 部分）。任何使一个人的参与变得可被查询之物
  都是缺陷（对照 L0：不存在用户名单，因为不存在用户注册的那个
  时刻）。

## 3. 联系卡

- **RZ-2.** 一张联系卡是**按关系区分**的：交给
  通信方 A 的卡必须（MUST）与交给通信方 B 的卡不可关联 ——
  不同的对密钥、不同的信箱。某一个通信方被攻陷只会暴露
  一段关系，而非接收者的整个世界。
- **RZ-3.** 卡的内容（规范 CBOR，如第 2 部分）：

| 键 | 名称 | 类型 | 说明 |
|---|---|---|---|
| 0 | `v` | uint | 格式版本，`1` |
| 1 | `id` | bytes(32) | 接收者的 Ed25519 身份密钥 |
| 2 | `kpair` | bytes(32) | 对密钥的秘密；下面的一切都由它派生 |
| 3 | `drops` | array | `d` 条内嵌的中继记录（完整的第 2 部分记录） |
| 4 | `validity` | uint | unix 过期时刻；应当（SHOULD）跟随内嵌记录的过期时刻 |

  派生（HKDF-BLAKE2s，套件 0x01）：此对的 SP-7 标签密钥为
  `K_tag = HKDF(kpair, "tag")`；信箱标识符为
  `box_id(drop, epoch) = PRF(kpair, "box" ‖ drop_index ‖ epoch)`，截断到
  16 字节，其中 `epoch = floor(unix_time / 86400)`（s）。drop 索引必须（MUST）
  进入派生：若每个纪元只有单一 id，两个串通的死信箱便能在
  那个纪元内关联起此对的各信箱。
- **RZ-4.** 卡经由带外（二维码、打印出的字符串、一位朋友）或
  经由一条既有的 ScrambNet 通道传递。一个联系人即是下限，一如 GR-10。

## 4. 死信箱与存入

- **RZ-5.** 死信箱集合由 `d = n = 4`（s）个中继构成，由*接收者*
  选取，这些中继应当（SHOULD）在路径选择所要求的那同一种意义上
  相互独立（OP-1 对死信箱同样适用）。一条消息的 `n` 份额
  必须（MUST）存入 `n` 个互不相同的死信箱 —— SP-7 延伸到存储：没有
  单独一个死信箱会同时持有任何东西的两份额。
- **RZ-6.** 一次存入就是一个普通的第 1 部分数据包，其链路终止于那个
  死信箱。`delta` 的末跳明文是 `box_id`（16 B）‖ `slot`
  （1840 B）；slot 就是第 1 部分 §4 的份额载荷，其尾部填充
  短了 16 字节。死信箱将 slot 原样存于 `box_id` 之下：它既读不了
  标签语义，也读不了份额内容（一份额 < `k`，且 SP-7
  使份额即便跨串通的死信箱也相互不可关联）。
- **RZ-7.** 存入是发完即忘。死信箱不得（MUST NOT）发出任何能够区分
  成功、未知信箱或满信箱的响应（静默一致性，如
  GR-4）。存储规则：1840 B 的定长 slot，每个信箱至多 `64`（s）个 slot，
  slot 过期 `7` 天（s），按最旧者优先逐出。

## 5. 取回

- **RZ-8.** 接收者在自己的链路上轮询它的每一个死信箱。
  知晓 `box_id` 即授予取回权（它由秘密派生而来、
  不可猜测）；slot 在过期时删除，而非在取走时删除（取走即删除的
  语义属于 OP-9 的地盘：一个窃得某 `box_id` 的对手不得
  能够静默地吃掉邮件）。
- **RZ-9（轮询纪律）。** 轮询必须（MUST）遵循一个独立于用户
  活动的时间表：带抖动的固定节奏（strawman：每 `15` 分钟 ±
  均匀 `5`），在用户空闲时也继续进行，并以相同的节奏向诱饵
  信箱 id 发出诱饵轮询。一次取回响应始终正好是 `b = 8`
  （s）个 slot，以与真 slot 不可区分的假 slot 填充。
  死信箱会在一个纪元内获知某信箱的轮询节奏与存入时刻 ——
  那是设计上的残余，受 RZ-10 约束，并在 OP-9 中被攻击。
- **RZ-10（纪元）。** `box_id` 按纪元轮换。一个死信箱不得（MUST NOT）能够
  跨纪元关联同一对的各信箱；取回协议中没有任何东西
  可以携带一个跨纪元稳定的值。

## 6. 刷新与失效

- **RZ-11.** 一张卡在带内续期：接收者在 `validity` 用尽之前，
  把下一张卡（新的 `kpair`、新的死信箱）作为一条普通消息存入
  此对既有的信箱。若某一对的每个死信箱都已死亡，或者
  卡已过期，则此对带外重新交换：一个联系人即是
  下限，再一次。
- **RZ-12.** 任何持有一张卡的人都可以填满它的信箱。每信箱上限（RZ-7）
  把洪泛损害限制在一段关系之内；存入定价（客户端
  谜题？）与死信箱存储经济学尚开放（OP-9）。

## 7. 密钥派生与纪元边界

- **RZ-13（唯一的 KDF 纪律）。** 一个对从 `kpair` 派生的每一个密钥与标识符都必须（MUST）出自单一纪律：HKDF-BLAKE2s，配以一个独特的、绑定用途的标签。具体而言：内容密钥为 `HKDF(kpair, "e2e-content")`（SP-1a），SP-7 标签密钥为 `HKDF(kpair, "tag")`，信箱标识符为 `box_id = HKDF(kpair, "box" ‖ drop_index ‖ epoch)` 截断到 `BOX_ID_BYTES`。没有任何值是通过在 `kpair` 上做原始加密钥 BLAKE2s、或通过任何第二种构造派生而来的 —— 早先的一份草案曾那样派生 `box_id`，本要求将其废止。标签分离意味着：某一个派生密钥被捕获或被削弱，不会向对手透露关于其兄弟密钥的任何信息，而整个关系由一次可审计的派生所统辖（`SA-4` 密钥分离论证，第 7 部分，恰恰依赖于此）。
- **RZ-13a（box_id 位宽）。** `BOX_ID_BYTES = 16`（128 位）（s）。一个死信箱只看到这个不透明句柄，绝不会看到 `kpair`；对于任何现实网络所持有的 `(pair, drop, epoch)` 信箱数量而言，128 位是抗碰撞的，并使 `box_id ‖ slot` 载荷保持在一个 `delta` 之内。
- **RZ-14（UTC 纪元边界宽限）。** 由于 `box_id` 按 UTC 纪元轮换（RZ-10），一个在 23:59（纪元 `E`）存入的发送者与一个在 00:01（纪元 `E+1`）轮询的接收者会寻址到不同的信箱，接收者会悄无声息地错过这封邮件。为防止此事，一个在纪元边界的宽限窗口之内轮询的接收者必须（MUST）**同时**轮询相邻两个纪元的信箱：始终轮询当前纪元；若处于某边界之后的宽限窗口之内，则轮询上一个纪元；若处于某边界之前的宽限窗口之内，则轮询下一个纪元。宽限窗口必须（MUST）超过最坏情况下的发送者/接收者时钟偏移加上存入到轮询的时延（strawman `EPOCH_GRACE_SECONDS = 3600`（s）），且 `SLOT_TTL_EPOCHS`（RZ-7）必须（MUST）使一个信箱在其自身纪元之后至少再可读一个纪元，这样那个额外的信箱才仍持有邮件。发送者在单一的 `epoch_of(now)` 之下存入；宽限是接收者一侧的读取规则。在 `poc/rendezvous.py` 中有演示（`epochs_to_poll`，测试 `test_deposit_before_boundary_polled_after_boundary`）。

## 8. 本部分不作决定之事

取回元数据的最小化（比轮询更聪明的取回、PIR 式的
手法及其真实代价）、删除语义、存入定价、死信箱
激励（OP-9）；死信箱集合独立性的验证（OP-1）；断网期间在
mesh 上的轮询（OP-6）。每一项都有编号 issue。
