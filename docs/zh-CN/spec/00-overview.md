# ScrambNet 规范 —— 第 0 部分：约定与结构

> **非规范性翻译。** 规范版本以英文为准（[en](../../en/spec/00-overview.md)）。

**状态：草稿（DRAFT）。** 本规范中的每一个数字都是一个待攻击的 strawman，
而非一项决定。通过 issues 攻击它；通过 PR 改动它。

## 如何阅读本规范

- 关键词 **MUST**、**MUST NOT**、**SHOULD**、**SHOULD NOT**、**MAY** 应按
  RFC 2119 所述解释。
- 需求是编号且稳定的：`SP-n`（share packet，第 1 部分）、`CH-n`（链路握手，第 1 部分 §5）、`GR-n`
  （gossip record，第 2 部分）、`PS-n`（path selection，第 3 部分）、`RZ-n`
  （rendezvous，第 6 部分）、`SA-n`（security argument，第 7 部分）、
  `ID-n`（推断数据集，第 8 部分）。issues 与
  PR 按编号引用需求。
- `OP-n` 引用指向
  [threat-model.md](../threat-model.md#open-problems) 中的开放问题清单。
- 一个合规的实现，实现它所声称的每一部分的每一条 MUST。

## 设计不变量

这四条不变量凌驾于规范中其余一切之上。一项违反其中
任意一条的提案都会被拒绝，无论它带来什么。

- **I-1（Kerckhoffs）。** 规范是完备的：一个仅有
  本文档而无任何其他知识的敌意实现者，必须（MUST）能够构建一个可互操作、
  安全性相当的节点。如果某个细节必须保密系统才能运作，那个
  细节就是缺陷。
- **I-2（无条件下界）。** 面对一个持有少于 `k` 份额的
  对手，消息内容的机密性不得（MUST NOT）依赖任何计算
  假设。分散之上的各层可以（MAY）是计算型的；而这条下界不是。
- **I-3（没有单点）。** 协议中没有任何一步可以要求一个方、一把密钥或一个地址，
  是无法由一个不受信任的替代物来取代的。这包括发现、
  更新与 bootstrap。
- **I-4（一致性）。** 一方在缺少相关密钥时，在线路上所能观察到的一切，
  都必须（MUST）与定长的均匀随机字节不可区分。没有任何明文形式的
  版本、标志或长度。

## 密码套件

套件标识符为一个字节，不在任何地方协商：套件按网络纪元固定，
并由数据包版本隐式携带（I-4 禁止明文
协商）。套件 `0x01`（strawman）：

| 角色 | 原语 |
|---|---|
| 链路握手 | Noise `XK` 模式，`Noise_XK_25519_ChaChaPoly_BLAKE2s` |
| 密钥交换 | X25519 |
| AEAD | ChaCha20-Poly1305 |
| 哈希 / KDF / PRF | BLAKE2s / HKDF-BLAKE2s |
| 签名（gossip 记录） | Ed25519 |
| 数据包格式 | Sphinx（Danezis–Goldberg 2009）参数，第 1 部分 |
| 分散 | 在 GF(2^8) 上逐字节的 Shamir 秘密共享 |

理由：无需硬件加速即可快速运行（只能在崭新笔记本上运行的
匿名工具，帮不到最需要它的人），不含任何奇异之物，每一项原语背后都有
十年之久的公开攻击。后量子说明：依照 I-2，机密性
下界本就能在量子对手面前存活；一个 PQ 握手（套件 `0x02`）是一项
计划中的升级，而非一场紧急事件。

## 编码约定

- 所有整数均为无符号，采用网络字节序（大端）。
- 凡字段跨越线路之处皆用定长（I-4）。可变长度数据
  仅存在于受 AEAD 保护的载荷内部，以 2 字节的长度前缀标示。
- gossip 记录采用规范 CBOR（RFC 8949 §4.2.1）—— 第 2 部分。

## 各部分

1. [第 1 部分 —— Share packet](01-share-packet.md)：承载
   一条消息的一份额穿过一条链路的那个定长单元。
2. [第 2 部分 —— Gossip record](02-gossip-record.md)：自签名的中继描述符，
   以及交换与抽样它们的规则。
3. [第 3 部分 —— 链路构建与路径选择](03-path-selection.md)：
   互不相交目标、无需自我申报的推断、守卫，以及
   小型网络的回退方案（OP-1）。
4. [第 6 部分 —— 会合与投递](06-rendezvous.md)：联系卡、
   分散的死信箱，以及以轮询进行的取回。
5. [第 7 部分 —— I-2 的安全性论证](07-security-argument.md)：对任意
   `k−1` 份额都独立于秘密这一点的证明、它所依赖的两个条件（系数随机性、
   密钥分离），以及对未被证明之事的一份坦诚陈述。
6. [第 8 部分 —— 推断数据集](08-inference-dataset.md)：客户端如何获取第 3 部分
   据以推断的 IP-to-AS 与粗粒度司法辖区映射，而没有权威 —— 一个可复现、内容寻址的
   产物、一个无需许可的透明性日志、被声明的首次使用即信任，以及该映射所承认、并喂给
   模拟器的那个错误率（OP-1 分布，roadmap 2.3）。

已规划、尚未起草：第 4 部分 —— 变色龙传输；第 5 部分 —— 断网
模式封装。
