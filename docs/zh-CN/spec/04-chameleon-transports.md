# ScrambNet 规范 —— 第 4 部分：变色龙传输

> **非规范性翻译。** 规范版本以英文为准（[en](../../en/spec/04-chameleon-transports.md)）。

**状态：草稿（DRAFT），也是最可能腐烂的那一部分。** 本部分陈述一个传输层的
威胁模型，以及一份诚实的现实性评估。它不承诺任何向外的机制，也不承诺在审查
军备竞赛中取胜。先读 §1 与那份现实性评估（§8）：这两者之间说清了本部分愿意
声明的那一件窄小的事，以及它拒绝声明的那件大得多的事。被标记为 `(s)` 的是
strawman 值。

架构层 L1（变色龙）与 L3（临时传输）住在这里；传输就是那个把一份份额的字节
带过审查者的东西。本部分归档在 OP-7（可达性与自举）之下，并且它依赖、而非
解决那个零接触自举问题（OP-7、GR-10）。

## 1. 这一决定，用两句话

- **本部分不声称 ScrambNet 赢得或维持住审查军备竞赛。** 它声称的恰恰相反，是
  关于它自身的重要性：那条机密性与分散的下界（I-2）**根本不**依赖于传输层。
  一个传输买到的是*可达性*——把一份份额的字节送到一个中继的能力——而可达性
  是被允许失败的，它沿着架构降级阶梯（L1→L2→L3→L4）往下走，并且在一次没有
  mesh 邻居的全面断网处，一路降到零，**而内容下界从不移动**（CT-16）。
- **因此那个诚实、站得住的声明是窄小的，且绝不可被放宽：** *我们并不让输掉
  这场传输竞赛变得不可能；我们让输掉它对机密性而言不构成灾难。* 一个审查者
  可以把可达性切到零；一个审查者仍然读不到 `k` 份份额以下的内容，因为那层
  保护从不骑在传输之上（CT-16、CT-18、CT-18a）。

下面的一切就是那个为这个窄小声明辩护的威胁模型，以及那份作为其脊梁的现实性
评估（§8）——本部分最重要的一节，而非一个附录。

## 2. 那个传输威胁模型（2026 年的审查者实际在做什么）

- **CT-1（声明你抵抗什么；沉默是一种让步）。「[规范性]」** 一份合规的传输
  描述必须（MUST）陈述，在 CT-2…CT-7a 那些敌手能力之中，它声称抵抗哪些、
  又让步哪些。一个未被声明的能力被当作已让步（I-1 完备性规则，用于传输）
  ——一个不点名一种攻击的传输，就没有防御过它。
- **CT-2（被动 DPI / 协议指纹识别）。** 审查者靠字节与结构签名、不读内容地去
  分类流；变色龙的工作是不呈现它自己的任何有辨识性的签名（CT-8）。
- **CT-3（TLS 指纹比对）。「[规范性]」** 审查者给 TLS ClientHello 打指纹。
  2026 年的基线是 **JA4 / JA4+**（FoxIO），而非已退役的 JA3：JA4 在哈希之前
  对密码套件与扩展**排序**并忽略 GREASE，所以它对主流浏览器如今所做的那种
  扩展顺序*随机化*是稳健的。因此一个合规的模仿必须（MUST）去匹配目标的
  密码套件*集合*、扩展*集合*、ALPN、supported-versions 与 GREASE *模式*——而
  不只是它的顺序，顺序 JA4 已不再区分。（一个只随机化顺序的模仿并不因此被
  隐藏。）
- **CT-4（SNI / ECH 检视）。** 审查者读取明文 SNI 以获知目的地名称。ECH 能
  隐藏它，但只是有条件地（CT-11）。
- **CT-5（主动探测 / 回连）。** 审查者连向一个可疑端点，检查它是否表现得像它
  所声称的那个东西；存活需要 CT-10。
- **CT-6（对流形状的被动统计分类）。「[规范性，声明残余]」** 审查者靠*统计*、
  而非字节去分类流：时序、体量、方向、突发结构，**以及熵**——并且那套特征集
  是开放的、由敌手选定的，包括习得的（ML）分类器。特别地，**高熵的「全加密
  流量」检测**会封锁那些看起来*太随机*、既无探测也无指纹匹配的流（自 2021 年
  底起在 GFW 上被观测到）。这有一个本部分其余内容所依赖的反直觉后果：
  **随机化或高熵的掩护流量是一个*更亮*的信号，而非更暗的**——最安全的掩护
  流量像一个非常常见的真实协议，绝不像噪声。CT-6 无法靠字节级模仿（CT-8）
  关闭；它诚实的答案在别的层上（CT-12、CT-15）。
- **CT-6a（TLS-in-TLS / 嵌套加密检测）。「[规范性，声明残余]」** 一个把
  ScrambNet 自己那已加密、I-4-uniform 的份额流量*塞进*一个被模仿的外层 TLS 流
  里去隧穿的传输，会留下有特征的记录尺寸与时序模式——一个*正在承载另一个 TLS
  握手*的 TLS 流——即便那外层握手逐字节完美（CT-3/CT-4 干净），DPI 也能标记
  它。这是对嵌套式规避的那个招牌攻击，且必须（MUST）被声明：一个模仿可以在
  握手上完美，仍在流结构上被逮住。它是字节模仿无法关闭的一个残余（它归属于
  CT-12）；点名它是 CT-1 所要求的。
- **CT-7（端点枚举——封锁已知之物）。「[规范性]」** 审查者批量发现并封锁已知
  的端点/网桥。分散（CT-15）与沿社交图谱的网桥分发（架构 L2、Lox）抬高成本；
  模仿根本不处理枚举。
- **CT-7a（端点发现——那条自举前线，声明为开放）。** 与 CT-7 有别：*一个被
  审查的用户当初如何获得一个未被封锁的端点，而且比审查者枚举它更快。* 这是那个
  网桥分发问题（Lox / 社交图谱），它归约到 **OP-7（零接触自举），而那是开放
  的。** 第 4 部分不解决它；它交叉引用它（GR-10、OP-7），而任何「端点是可靠
  可发现的」声明都是一个本部分拒绝作出的、无依据的承诺。
- **CT-7b（协议白名单——那个极限情形）。** 审查者只许可一份协议/目的地的
  允许清单，并丢弃其余（被观测到：伊朗的国家网络白名单，2025–2026）。对此，
  模仿一个*被允许的*目的地是唯一的一手棋，而即便它也会在审查者接受那个附带
  代价时失败（§8、CT-14）——一路到一次全面断网，那里没有任何传输能触及
  任何东西（CT-18a）。

## 3. 模仿纪律（那台无尽跑步机，被变为规范性的）

- **CT-8（没有静态的项目签名；以被部署的样子去模仿）。「[规范性]」** 一个
  变色龙传输不得（MUST NOT）呈现一个静态的、项目特有的线路签名，并且必须
  （MUST）模仿一个目标协议*被实际部署的样子*、而非一个理想化的样子。一个手搓
  或冻结的栈其本身就是一枚指纹，是不合规的。
- **CT-9（那条 uTLS 漂移条款）。「[规范性]」** 一个 uTLS 式的模仿必须（MUST）
  跟踪目标*当前被部署的* ClientHello，并且必须（MUST）声明它所模仿的目标版本
  （CT-20）。对 JA4（CT-3）而言，那个区分器是密码与扩展*集合*、ALPN、
  supported-versions 与 GREASE 模式上的背离——这些随每一个浏览器发布而漂移，
  所以一个冻结在版本 N 的模仿，一旦真实人群迁移到 N+1 就变成一个区分器。这是
  一台**没有终态的维护跑步机**：不存在一个使工作完成的版本（§8）。那条下界
  不得（MUST NOT）依赖于跟上它（CT-16）。
- **CT-9a（优先一个高人群目标——出于匿名集的理由，而非经济的理由）。
  「[规范性]」** 一个合规的部署应当（SHOULD）模仿一个高人群、快速移动的目标
  （一个主流浏览器的 TLS），而非一个小众的，出于两个*机械的*理由：那个大群
  是一个更好的匿名集（有更多真实流可供藏身），而一个快速打补丁的目标会缩短
  那个 CT-9 过期窗口。本条款**不**作出任何经济性声明，说那个群「太贵以至于
  封不了」——那个赌注是 CT-13，已声明为可被推翻，而 2026 年的记录（一个国家级
  审查者封锁了那个最大的 ECH 群，§8）表明它能被输掉。

## 4. 主动探测的存活

- **CT-10（存活一次回连探测；沉默本身就是一枚指纹）。「[规范性]」** 一个
  变色龙端点必须（MUST）存活一次主动探测：它必须（MUST）完成一次它所模仿协议
  的*真实*、有效的握手，并向一个未经认证的探测者提供貌似可信的掩护行为（例如
  真实的 TLS 终结，代理到貌似真实的内容），只向一个证明了预共享秘密的客户端
  揭示那个隐蔽服务。那个现代模型是终结真实-TLS-并代理到一个真实站点，**而非**
  那个更老的保持沉默模型：*对一个未经认证的探测者保持沉默本身就是一个可检测的
  行为*（有特征的超时、字节接受阈值、重放处理），且是不合规的。
- **CT-10a（那个预共享秘密是一条网桥线——它的分发是开放的）。「[规范性]」**
  在 CT-10 中把一个真实客户端与一个探测者区分开的那个秘密是一条**网桥线**，
  而**它的分发是 OP-7 / GR-10，已声明为开放。** CT-10 假设一个秘密已被投递；
  它**不**解决投递。探测抵抗与自举是两个分开的问题，而把它们混为一谈（假设
  那个秘密不知怎么已经到处都是）正是 CT-7a 所禁止的那个错误。
- **CT-10b（那个成本会使运营者池变稀薄）。** 真实的掩护内容、真实的证书与真实
  的终结，是一项常驻的、逐端点的运营负担。抬高那道门槛恰恰就是那个使志愿者-
  运营者池缩小之物——那就是那个可持续维护问题（§8），戴着一顶运营的帽子。

## 5. ECH 姿态（不过度声称）

- **CT-11（ECH 是机会主义的、受可用性所界的，绝非一条下界）。「[规范性]」**
  一份合规的描述不得（MUST NOT）把 ECH（Encrypted Client Hello）呈现为一个
  已解决的 SNI 防御。它陈述：(a) ECH 仅在那个前置提供商部署了它、客户端支持
  它、**并且那个携带 ECH 配置的加密-DNS 查询成功**之处隐藏 SNI——封锁或降级
  那个 DNS，ECH 就会悄无声息地不启用，而那正是实际的 2026 年失败模式；(b)
  2026 年的服务器侧部署是一个*少数但在增长*的切片，集中在少数几个大型前置
  提供商处，而非那条长尾，所以「SNI 被隐藏了」对大多数目的地在大多数时候是
  假的；(c) **「彻底封锁 ECH」是一个被观测到的审查者回应**（一个国家级审查者
  自 2024 年底起封锁去往一个主要提供商的 ECH 连接），而 ECH 依其构造无法反制。
  ECH 是一项机会主义的改进，而非一个保证。*（ECH 规范是 IETF TLS 工作组的
  ESNI/ECH 工作；本部分不钉定一个已发布的 RFC 编号，该编号在起草时尚未被确认
  ——引用那份当前文档，而非一个可能是错的编号。）*
- **CT-11a（降级，别泄漏）。「[规范性]」** 在 ECH 不可用或被封锁之处，一个
  合规的传输必须（MUST）降级到那把阶梯的下一级（L2 临时网桥），而非回退到
  一个有辨识性的明文-SNI 流。那条降级路径、而非 ECH，才是那个保证。

## 6. 那个流关联残余

- **CT-12（模仿无法击败流形状；把这说出来）。「[规范性，声明残余]」** 不得
  （MUST NOT）声称字节级模仿击败了流形状关联（CT-6）、嵌套-TLS 检测（CT-6a），
  或一个把入口与出口相关联的全局被动观察者。时序、体量、方向、突发结构与嵌套
  会穿过一个完美的模仿泄漏出来。这些是模仿*无法*关闭的残余，且必须（MUST）
  被声明、而非被隐藏。唯一诚实的答案在别的层上——分散把一条消息的形状摊到
  多份掩护流量上（CT-15，一个*可用性*性质，而非一个形状隐藏性质），而偏执档
  混合（架构 L2）以延迟换形状抵抗——绝非那个模仿本身。网站谕示（website-
  oracle）与入口侧确认攻击都归约到这同一个关联残余，以及那一行威胁模型早已
  声明为超出快速档范围的全局被动敌手。

## 7. 把份额分散到多样化的掩护流量上（那个规范性裁断）

- **CT-15（那个裁断：多样性帮助可用性，损害不可观测性；买下前者，为后者付费
  并声明之）。「[规范性]」** 把一条消息的 `n` 份份额载在*不同的掩护类型*上
  （一份走 TLS，一份走 WebRTC，一份走 mesh）是一个两面的决定，按如下解决：
  (a) 不得（MUST NOT）假设它改善了**不可观测性**——`n` 个掩护是 `n` 枚要搞对
  的指纹（CT-3）、`n` 台跑步机（CT-9），还有一个货真价实的新危害：一个
  **跨掩护关联面**。一个看见一个 TLS 流、一个 WebRTC 流与一个 mesh 突发在
  时序/体量上相关的敌手（CT-6），能把它们链接为一条消息的那些份额，*而不必
  攻破任何单个模仿*——多样性并不使那个信号变暗，它能使它变亮；
  (b) 它被允许，并且**严格作为一个可用性措施**而被看重：没有任何单个掩护的
  封锁能杀死投递（`k < n` 已经买到这个），而端点枚举（CT-7）现在必须*逐个地*
  对各掩护成功——这针对一个*一次封一个*掩护的审查者抬高了审查者的成本，并且
  针对一个协议白名单（CT-7b）或一次全面断网（CT-18a）提供**不**出任何好处，
  后两者一举封锁所有掩护。
- **CT-15a（把它当作可达性来卖，绝不当作伪装）。「[规范性]」** 一个合规的
  客户端不得（MUST NOT）向用户把多掩护分散呈现为*更强的伪装*；它可以（MAY）
  把它呈现为*更强的可达性*。把两者混为一谈，与 ID-12a 为那张映射所禁止的那个
  关联-对-内容的类别错误是同一个，为传输而重述：多掩护改善一个可用性性质，
  而不改善一个模仿性质。
- **CT-15b（最小掩护集被留为开放；声明以实际所运行之物为界）。「[规范性]」**
  第 4 部分**不**强制一个最小掩护集——强制 `n` 个掩护就是强制 `n` 台项目也许
  无力配备人手的维护跑步机（§8）。一个掩护集开放/未指定的客户端不得（MUST
  NOT）声称任何*定量的*可用性性质（没有一个已陈述、实际所运行的 N，就不能
  「抵抗跨 N 个掩护的枚举」）；它只可以（MAY）声称那个*定性的*「没有单个掩护
  的封锁能杀死投递」，并且只在它实际运行 ≥2 个独立掩护且 `k < n` 之时。是否为
  那个分散投递默认而要求 ≥2 个掩护，是一个所有者的决定（§8）。

## 8. 那份诚实的现实性评估（那条脊梁）

*（本节就是本部分本身，而非一个附录。它以第 8 与第 11 部分的那种 §残余
声音写就。）*

**本部分不承诺任何向外的机制，且绝不可假装有。** 它是一个关于项目在何处脆弱
的裁断，以全强度陈述：**传输层是项目最弱、最可能腐烂的那一层，而诚实的姿态是
把这说出来，并这样去设计，使那条下界永不依赖于它。**

**那台 uTLS 漂移跑步机（CT-9）。** 一个冻结在某个浏览器版本的模仿，在真实人群
往前走的那一刻就变成一个区分器——一个更小、更陈旧的群是一个*更亮*的信号，
而非更暗的。不存在一个使工作完成的版本。对 JA4 而言顺序已不再要紧，但密码/
扩展*集合*仍随每次发布而漂移，所以这台跑步机比它对 JA3 时要慢，却并不停止。
项目赢不了这个；它要么在它上面跑，要么从它上面下来，而 CT-16 就是那个让下来
变得可存活的决定。

**ECH 的 2026 年现实（CT-11）。** ECH 仅在提供商、客户端*以及那个加密-DNS 查询*
全都成功之处隐藏 SNI，而在 2026 年那是少数目的地。「彻底封锁 ECH」已经被一个
国家级审查者用来对付那个最大的前置提供商，而 ECH 无法反制。ECH 是一项受部署
所界的机会主义改进；那条下界是那条降级路径，绝非 ECH。

**那个经济论证及其反例（CT-13/CT-14）。** 「封锁我的代价高过它所赚」是一个真实
的威慑，也是一个虚假的保证。2026 年的记录有反复出现的反例，审查者宁付巨大的
附带代价也不许可规避：一个国家级监管者封锁去往一个主要提供商的 ECH（自 2024
年底起）；一个国家网络**协议白名单**只许可一份短的允许清单（伊朗，
2025–2026）；以及动荡期间的**彻底互联网断网**（伊朗，2025 年年中，以及
2026 年年初又一次）。每一个都是一个审查者选择控制而非商业。那个经济赌注是
概率性的：它对一个看重附带代价的审查者有效，对一个已表明自己不在乎的审查者
失效。我们把这陈述出来，而非把那个经济性含糊地当作已定论。*（这些是作为被
观测行为的类别被引用的；一份合规的写作应当附上日期与司法辖区，并且必须（MUST）
舍弃任何它站不住的反例——一个错的反例比没有更糟，CT-14。）*

**那个令人不安的问题，已被回答（那个中心已声明的残余）。** *一个化名的志愿者
项目是否拥有一场传输军备竞赛所要求的那种可持续维护能力？* Tor 有带薪员工、一个
被资助的可插拔传输生态系统，以及多年的机构记忆，而它*仍然*会在对抗铁了心的
审查者时输掉一些回合。一个化名、无名册的项目——一个按设计（I-3，以及第 10/11
部分的治理）拒绝那种能让它把一个传输更新一次性推送给所有人的中心协调的项目
——拥有**更少**的那种能力，而非更多。因此那个诚实的答案是**不，不可靠地
拥有。** 那场传输军备竞赛恰恰奖赏项目出于原则性理由已放弃的那种被资助的、被
协调的、身份绑定的维护。我们应当预期那个模仿层会落在后头。

**而这正是为什么没有任何承重之物坐在它上面。** 赢一场传输军备竞赛所需的维护
能力，恰恰是我们所没有的，也恰恰是那条下界所不要求的。我们预期那个模仿层会
落在后头；那个架构是一个它可能落后也无妨的赌注——与那个架构已经为洋葱带所作
的那同一个赌注（「若这整个计算层某天倒下，网络并不会变得可读——它只是变得
不那么方便」），以及第 10/11 部分为更新所作的赌注（拒绝那次推送，付那个延迟，
把它陈述出来）。这是关于一种我们所缺能力的诚实悲观，被转化为那个使这个短缺
不构成灾难的设计理据——而非失败主义。

**那把阶梯的底部，被承认（CT-18a）。** 那把降级阶梯 L1→L2→L3→L4 有一个底部，
而那个底部还有一个底部。在一次**没有物理 mesh 邻居可及的全面断网**处，没有
任何传输能触及任何东西，且**没有任何消息被投递——到此为止。** 我们不让*那个*
可存活。那条 I-2 内容下界依然成立（没有任何东西被*揭示*；送不出去的东西读不到），
但可达性为零，而那条下界在那一点上是*完好且无用的*：一条无法离开设备的消息的
完美机密性。那个诚实的声明不是「通信总能穿过去」——而是「机密性从不依赖于
传输，而当传输死去，那个秘密就随它一起死去，未被投递，而非被暴露」。一个在
一场炽热断网里的 mesh 节点其本身就是一个物理上可定位的行为（第 5 部分、OP-6），
所以即便是那最后一级也是一个明确的、危险的选择加入，而非一个保证。

## 9. 那道不变量护卫

- **CT-16（那条下界不依赖于赢得那场竞赛；机密性 ≠ 可用性）。「[规范性]」**
  没有任何机密性或分散的保证（I-2）被允许（MUST）依赖于任何变色龙传输成功、
  依赖于一个模仿保持当前（CT-9）、依赖于 ECH 可用（CT-11），或依赖于那个经济
  论证成立（CT-14）。传输买到的**只是可达性**。I-2 保证的是**机密性**
  （`k` 以下的内容不可读），一个*已投递-对-未投递*的性质，它对是否有任何东西
  被投递保持沉默——**而非**一个可读-对-不可读的投递保证。传输失败必须（MUST）
  沿那把阶梯往下降级（L1→L2→L3→L4），并在底部降到零可达性（CT-18a），
  **绝不**损害 `k` 以下的内容。一个输掉那场传输竞赛就输掉那条下界的设计是
  不合规的。
- **CT-17（最小化依赖；别承诺取胜）。「[规范性]」** 一个合规的姿态必须（MUST）
  最小化那条下界对模仿的依赖，而非承诺去维持它。在模仿与降级都回应一种威胁
  之处，本部分必须（MUST）优先把那条降级路径当作那个保证，并把那个模仿当作
  那个便利（那条架构自己的格言：一切能过期之物都是一个便利）。
- **CT-18（那个已声明的上限：没有军备竞赛取胜的声明）。「[规范性]」** 第 4
  部分不得（MUST NOT）声称 ScrambNet 赢得或维持住那场审查军备竞赛。它作出的
  唯一声明是 CT-16 的：那个传输层*被允许输*，而那条下界不输。任何声称传输层
  级无敌、一场「可持续的」军备竞赛胜利，或 ECH-已解决的文本、UI 或 README 都是
  不合规的，且必须（MUST）被改正——包括那一行威胁模型的国家级审查者行，本部分
  把它修订为将*可达性*（有争议，可能降至零）与*内容*（无条件受保护，与传输
  无关）拆开。
- **CT-18a（那个终态情形被陈述，而非被隐藏）。「[规范性]」** 一份合规的写作
  必须（MUST）明确陈述 CT-18 的那个终态情形：在一次没有 mesh 可及的全面断网处，
  可达性为零，且没有任何消息被投递；那条内容下界成立，但对那条未被投递的消息
  而言是无用的。「我们让输掉那场传输竞赛*对机密性*可存活，而非对投递」是那个
  精确的声明，而没有任何措辞可以被写成暗示投递是有保证的。

## 10. 运营诚实面

- **CT-19（诚实地浮现那个传输姿态）。「[规范性]」** 一个合规的客户端必须（MUST）
  在那个既有的诚实面（PS-9）上浮现它当前的传输姿态：它正在用哪个掩护、ECH 是否
  *实际*在生效（而非仅仅被尝试），以及传输可达性——与那条 I-2 下界不同——携带
  **不出**任何保证，且可能失败到零。那个 UI 所陈述的消息：*你的内容下界成立；
  你触及网络的能力不成立。*
- **CT-20（声明模仿的过期程度）。「[规范性]」** 一个合规的部署应当（SHOULD）
  声明它的模仿目标有多当前（CT-9），那是那张映射的实测错误率（ID-12）的传输
  类比，从而用户与那个模拟器能把一个过时的模仿当作它所是的那枚指纹，而非悄无
  声息地信任它。

## 11. 此处引入的需求

- **CT-1 / CT-2 / CT-3 / CT-4 / CT-5** —— 声明你抵抗什么；被动 DPI；JA4 TLS
  指纹识别（集合 + GREASE，而非顺序）；SNI/ECH 检视；主动探测。
- **CT-6 / CT-6a** —— 被动统计/熵/ML 流分类（随机性是一个更亮的信号）；
  TLS-in-TLS 嵌套检测——二者皆是模仿无法关闭的残余。
- **CT-7 / CT-7a / CT-7b** —— 端点枚举 对 端点*发现*（那条 OP-7 自举前线，
  声明为开放）；协议白名单。
- **CT-8 / CT-9 / CT-9a** —— 没有静态签名；那台 uTLS 漂移跑步机；出于匿名集
  理由、而非一个经济承诺去优先一个高人群目标。
- **CT-10 / CT-10a / CT-10b** —— 以真实掩护存活一次探测（沉默是一枚指纹）；
  那个预共享秘密是一条网桥线，它的分发是 OP-7；那个成本使运营者池变稀薄。
- **CT-11 / CT-11a** —— ECH 是机会主义的、依赖 DNS 的、封锁-ECH-已被观测的，
  不是一条下界；降级而非泄漏明文 SNI。
- **CT-12** —— 模仿无法击败流形状/嵌套/关联；那些答案在别的层上，绝非那个
  模仿。
- **CT-15 / CT-15a / CT-15b** —— 多掩护分散帮助可用性、损害不可观测性，添加
  一个跨掩护关联面；把它当作可达性而非伪装来卖；声明以实际所运行的掩护为界。
- **CT-16 / CT-17 / CT-18 / CT-18a** —— 那条下界从不依赖于传输；机密性 ≠
  可用性；没有军备竞赛取胜的声明；那个零可达性终态情形被陈述，而非被隐藏。
- **CT-19 / CT-20** —— PS-9 上的诚实传输姿态；已声明的模仿过期程度。

CT-16 与 CT-18 是承重的两条：那条下界不依赖于赢得那场传输竞赛，而本部分不作出
任何那场竞赛被赢得的声明。那个传输层是项目预期会在其上输掉一些回合的那一层，
而它被这样架构，使输掉它们付出的是*可达性*、绝非*机密性*——一路到那个可达性
为零、而那条未被投递的秘密仍是一个秘密的终态情形（CT-18a）。打破本部分，靠
点名一种 CT-2…CT-7b 漏掉的审查者能力、一条越过 CT-18 承诺赢得或维持那场军备
竞赛的条款、一处那条 I-2 下界被弄成依赖于一个传输成功的地方，或者一条把多掩护
分散越过 CT-15a 卖作伪装的途径。那就是邀请，以那种家宅之声。
