# ScrambNet 规范 —— 第 3 部分：链路构建与路径选择

**状态：草稿（DRAFT），也是本规范中最不稳定的部分。** 这是*运维*安全的承重墙
（I-2 所保障的内容下界没有它也能成立，但抗关联保护与整套 k-路径的故事都栖身于此）。
临时取值以 `(s)` 标记。disjoint（互不相交）性的验证问题即 OP-1，且公开地悬而未决；
本部分陈述目标，并给出一个可供攻击的首个机制。

## 1. 范围，以及为什么这很难

分散（第 1 部分）使内容在被捕获的 `k` 份额以下无条件安全。只有当 `n` 条份额链路
真正互不相交时，那条保证才在*运维*意义上成立——否则对手的单个观测点便能看见 `k`
份额，而那条下界虽在数学上完好无损，却永远无法企及。本部分决定一个客户端——它仅持有
自己那份可验证的 gossip 抽样（第 2 部分），并无任何可信地图——如何选出 `n` 条让对手
无法廉价地横跨其上的链路。此处的一切都必须能抵挡这样的中继：它们对一切都撒谎，唯独
对其签名所绑定之物不能（GR-2）。

## 2. 互不相交性目标

- **PS-1.** 一条消息的 `n` 条链路必须（MUST）*按节点互不相交*：没有任何中继出现在
  其中两条之上。这是下界，只要抽样足够大便始终可强制施行。
- **PS-2.** 客户端应当（SHOULD）另行追求如下目标，按价值递减、难度递增的顺序：
  **按 AS 互不相交**（没有任何两条链路在守卫或出口处共享同一自治系统），其次
  **按司法辖区互不相交**（没有任何两条共享同一法律辖区）。它无法满足的每一层级都
  必须（MUST）向用户报告，而非悄然跳过（PS-9）。
- **PS-3.** 在同一条链路内，守卫、中间节点与出口必须（MUST）按节点各不相同，并应当
  （SHOULD）按 AS 各不相同。一条守卫与出口共享同一 AS 的链路，是送给端到端关联的
  大礼，只要存在任何替代方案便禁止（MUST NOT）使用。

## 3. 无需自我申报的推断

- **PS-4.** GR-3 禁止中继申报其位置，因此客户端从每个中继的 `addrs` 出发，使用
  *自己的*数据集（例如一份定期刷新的 IP-到-AS 映射）来推断该中继的 AS 与司法辖区，
  绝不采信中继自身所言。该数据集的分发本身必须（MUST）遵守 I-3：不存在任何单一的
  权威来源（候选设计即 OP-1）。
- **PS-5.** 推断是不确定的，客户端必须（MUST）如此对待它：当某中继的 AS 或司法辖区
  未知时，它便计为与其他每一个未知项*可能共享*——取保守假设，绝不取乐观假设。

## 4. 守卫

- **PS-6.** 每个客户端维护一小组**守卫中继**（临时方案：每个链路位置一个主守卫，
  按月而非按分钟的节奏轮换），沿用 Tor 的守卫论证：快速轮换入口点会成倍放大最终抽中
  一个敌意入口的概率。各守卫之间必须（MUST）选为按 AS 互不相交，使得 `n` 条链路不会
  在入口处汇集穿过同一个 AS。
- **PS-7.** 守卫的选取按*已验证*带宽（GR-7）加权，绝不按声称的带宽；一个带有无法
  验证之声称的中继，被当作低带宽处理，而非高带宽。

## 5. 小型网络：降级，并把它说出来

- **PS-8.** 当客户端已验证的抽样无法提供 `n` 条按 AS 互不相交的链路时，它必须
  （MUST）按固定顺序回退——按 AS 互不相交 → 按节点互不相交 → 独立抽取——并且不得
  （MUST NOT）悄然像更强的性质仍然成立那样继续下去。当估计出的可行规模未达标时，
  参数可以（MAY）下调（小型网络模式：`n = 2, k = 2`，并尽力而为地做到互不相交）。
- **PS-9.** 客户端必须（MUST）将一条消息实际达到的互不相交层级，以非专家也能正确
  读懂的措辞公开出来：今天的人群很小；这就是你买到的东西。内容下界（I-2）与关联层级
  是彼此独立的陈述，必须（MUST）分别展示。

- **PS-10（抗女巫的规模估计）。** 可行规模的估计必须（MUST）只计入独立验证过的中继
  与观测到的 AS 多样性，绝不计入原始的记录条数，以免对手用女巫节点把网络吹胀，从而
  诱使客户端采用其多样性为假的完整参数（与 OP-2 相关联）。

- **PS-11（被认定的互不相交性并非真正的互不相交性）。** 客户端所构建的保护，其优劣
  上限不过等同于它的推断数据集，客户端必须（MUST）把该数据集的错误率当作头等的安全
  参数，而非实现细节。模拟器（`poc/network_sim.py`，§1）将对手所利用的*真实底况*与
  客户端的*认定*区分开来，并扫过推断错误率：随着错误上升，按 AS 互不相交的选取会部分
  沦为幻觉，内容攻破率与关联泄漏二者都单调上升。有两条推论具有规范性：（a）对于
  **随机**推断误差（噪声，一份仅仅是不准确的地图），该误差对**关联的侵蚀远快于对
  内容的侵蚀**——一次内容攻破仍需对手同时处于 `≥ k` 条链路之上，故在元数据率先劣化
  之际下界依然成立；UI 不得（MUST NOT）把一个很低的内容攻破数字呈现得仿佛它同时也
  为关联设定了界限。这种不对称性**仅对随机误差**成立；一份*被对手择定*的地图不是
  噪声（见 PS-12）；（b）更稀薄的 **gossip 抽样**（PS-10，I-3）会
  更早地迫使回退：一个认识的中继太少的客户端根本无法构建按 AS 互不相交的链路，只能
  跌落至 `none`，此时攻破率陡然跳升（§2）。因此可行规模的估计（PS-10）必须（MUST）
  以*可达*的抽样为准，而非以整个网络为准。零错误、完整视图下的数字是最佳情形；一个
  合规的客户端必须（MUST）呈现其从真实、带噪、局部的视图中所达到的层级（PS-9）。
- **PS-12（一份敌意地图不得将选取操纵到对手之上）。** `[claim-critical]` 一份
  *被对手择定*的地图不是随机误差，PS-11(a) 的不对称性**不**能防御它。一份对手所控制的
  地图对按 AS 互不相交的选取握有两个杠杆：给对手自己的同址中继以*互不相同的*伪造 AS
  （从而它们永不彼此排除），并给*诚实*中继以*相互碰撞的*伪造 AS（从而一旦链路 1 选中
  一个诚实中继，其余每一个诚实中继看起来都与之按 AS 共享，于是被滤除）。诚实候选池
  便在首次抽取之后塌缩，客户端几乎完全从对手中继里选出链路 2…`n`——把对手*确定性地*
  落在 `≥ k` 条链路的守卫**与**出口之上，一次*内容*攻破，而客户端仍认定自己达到了
  按 AS 互不相交，并且不发出任何回退警告。已对 `poc/network_sim.py` 演示：一份操纵
  地图将内容攻破率从约 0% 推到**在约 15% 的对手占有率下达到 100%**（相比之下，一份
  诚实地图在 35% 时为个位数的低攻破率）。所以**一份坏地图能够触及内容，而不只是关联**
  （这更正了此前一处过度陈述；第 8 部分 ID-8a 已被更正以相符）。一个合规客户端必须
  （MUST）施加的防御：
  1. **不要让地图独自就能塌缩诚实池。** 客户端不得（MUST NOT）构建这样一个链路集合：
     其中超过一个有界份额的链路，就其所声称的相互互不相交性而言，依赖于客户端无法
     *独立*佐证其为相异的中继（GR-8 来源混合，PS-10「只计数独立验证过的」）。如果
     被认定为互不相交的选取会从一个被地图弄得可疑地小的池里抽取链路 2…`n`，客户端
     必须（MUST）将其当作一个回退/异常状况（PS-8、PS-9），而非一次成功。
  2. **一份蕴含不可信 AS 结构的地图本身就是一个异常。** 若在某份地图之下，客户端的
     *可达诚实抽样*塌缩为一个或少数几个 AS，而被对手塑形的其余部分却极度多样，这便是
     操纵的签名；客户端应当（SHOULD）将其作为地图异常 gossip 出去（第 8 部分 ID-10）
     并回退。
  3. **重建才是真正的防御。** 一份操纵地图无法从公开输入复现（第 8 部分 ID-5a）；
     一个重建了的、或与一个重建了的诚实对端取得一致的客户端，会拒绝它。在此之前，
     客户端必须（MUST）把一份未验证地图的互不相交性声称当作未验证，而非已达到（PS-9）。
  诚实的残余仍在：在一个已接受一份未验证操纵地图、且尚无法重建的客户端的日蚀窗口
  之内，内容下界可能坍落。这由 `k`/`n` 的余量以及上述防御来界定，而非由一个「它不会
  发生」的声称来界定。

## 6. 本部分不作决定之事

互不相交数据集的无信任分发，以及对所选集合是否如所声称般互不相交的形式化验证
（OP-1）；诚实的可行规模阈值，以及 `n = 2, k = 2` 究竟是否值得运行（OP-3）；守卫
轮换的经济学；在断网网状网上的路径选择——那里 AS 与司法辖区均无意义（OP-6）。
`poc/network_sim.py` 是本部分背后那个可运行的临时方案——先攻击它的模型，再攻击
这段文字。
