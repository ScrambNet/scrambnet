# ScrambNet 规范 —— 第 2 部分：Gossip Record

> **非规范性翻译。** 规范版本以英文为准（[en](../../en/spec/02-gossip-record.md)）。

**状态：草稿（DRAFT）。** strawman 取值以 `(s)` 标记。本部分所倚赖的女巫/eclipse
问题即 OP-2，且刻意保持开放。

## 1. 范围

gossip record 是一个中继借以存在的自签名描述符。不存在
目录、不存在权威、不存在注册（I-3）：一个中继就是它所签名的那组
记录，而网络的地图就是每个客户端所持有的那份可验证抽样。

## 2. 记录格式

- **GR-1.** 一条记录是一张规范 CBOR 映射（RFC 8949 §4.2.1），编码后
  至多 `1024` 字节（s）。更大的记录必须（MUST）不经读取即丢弃。
- **GR-2.** 字段（整数键；为前向兼容，未知的键必须（MUST）被忽略，
  但受签名覆盖）：

| 键 | 名称 | 类型 | 说明 |
|---|---|---|---|
| 0 | `v` | uint | 格式版本，`1` |
| 1 | `id` | bytes(32) | Ed25519 身份公钥 —— 中继的名字 |
| 2 | `onion` | bytes(32) | 用于链路握手的 X25519 密钥；必须（MUST）在 ≤ 7 天内轮换（s） |
| 3 | `addrs` | array | 端点：`[transport-id uint, blob bytes]` 对 |
| 4 | `bw` | uint | 声称的持续带宽，kB/s —— 一项*声称*，见 GR-7 |
| 5 | `created` | uint | unix 时间，必须（MUST）向下取整到小时（GR-5） |
| 6 | `expiry` | uint | unix 时间，必须（MUST）≤ `created` + 7 天（s） |
| 7 | `sig` | bytes(64) | 在键 7 缺席的规范编码之上的 Ed25519 签名 |

- **GR-3.** 一个中继不得（MUST NOT）发布关于自身的地理或司法辖区
  声称。客户端用自己的数据从 `addrs` 推断出 AS 与司法辖区
  （OP-1）；自我申报的位置是一个攻击面，而非信息。
- **GR-4.** 签名有效性、尺寸上限、过期以及时间戳取整都必须（MUST）
  在一条记录被存储或转发之前全部检查完毕；失败者被
  静默丢弃 —— 不得向该记录的发送者暴露任何将「格式错误」与「已过期」
  区分开来的错误。
- **GR-5.** `created` 取整的存在是为了阻止以时钟偏移对中继做
  指纹识别。客户端必须（MUST）将两条带相同 `id` 的记录视为同一个中继，并
  只保留最新的 `created`。

## 3. 交换与抽样

- **GR-6.** 记录在既有链路上以及在本地 mesh（第 5 部分）上传输，
  以定长批次搭载：一个 gossip 批次是 `8` 条记录（s），
  填充到定长，每个对等体每 `10` 分钟（s）至多交换一次。
  一个节点以其所存记录的一份均匀抽样来回应抽样请求；
  它不得（MUST NOT）以一份因请求者身份而有偏的抽样来回应（那正是显而易见的
  eclipse 杠杆）。
- **GR-7.** `bw` 是一项声称。客户端应当（SHOULD）通过在不暴露探测者的
  链路上做随机探测来验证声称，并应当（SHOULD）按已验证带宽——而非声称带宽——为
  路径选择加权。探测设计尚开放（OP-2）。
- **GR-8（来源混合）。** 一个客户端所存的抽样必须（MUST）混合来自
  相互独立的来源类别的记录 —— 至少包括：沿社交图谱的网桥（Lox 式）、
  gossip 交换，以及直接探测 —— 并且不得（MUST NOT）允许任何单一类别
  超过抽样的一个可配置比例（strawman 为 1/2）。这是在 OP-2 产出
  更强之物之前的 eclipse 防御。
- **GR-9.** 新身份按设计就廉价（无需注册），因此本部分中
  没有任何内容可以从身份成本中假定抗女巫性。任何需要
  抗女巫性的机制，都必须从已验证的资源（带宽、
  由客户端自身观测到的长期在线时长）或社交图谱中获取它——绝不
  从记录本身获取。

## 4. Bootstrap

- **GR-10.** 一个崭新的客户端必须（MUST）能够从单独一行带外
  网桥信息起步（一个二维码、一个打印出的字符串、一位朋友的消息），其中含有
  一条记录外加一条传输提示。零联系人 bootstrap 即 OP-7，开放。

## 5. 带宽探测协议（闭合 GR-7）

GR-7 说 `bw` 是一项声称，应当（SHOULD）通过「在不暴露探测者的链路上做随机探测」
来验证，随后便声明探测设计尚开放。本节即是那份设计。探测恰好回答一个问题
——*我，这个客户端，此刻能通过一条不指明我的链路，经这个中继推送多大的吞吐
量？* —— 而它只为提出此问的客户端回答。**不存在**任何已发布的、共享的或权威的
带宽数字：Tor 的带宽权威恰恰就是 I-3 拒绝给我们的那个中央分配者（PS-10、GR-9），
因此每个客户端都自行导出其各自的已验证数字，并据此为其各自的路径选择（PS-7）
加权。

### 5.1 测量，以及它是何者的纯函数

- **GR-11（已验证带宽是一项逐客户端的自我测量，绝非一个已发布的数字）。**
  `[claim-critical]` 一个客户端对中继 `R` 的已验证带宽，记作 `vbw(R)`，必须（MUST）
  被计算为该客户端**自己**所观测之输入的确定性函数：
  ```
      vbw(R, epoch) = probe(circuits_through_R, bytes_sent, timestamps_seen)
  ```
  而不计算任何中继、对等体或任何第三方所断言之物。`vbw` 是一个本地变量，而非
  一个网络值：两个诚实客户端探测同一个 `R` 会导出**不同的** `vbw(R)`（它们各自的
  路径、各自的拥塞、各自的时刻），而这是正确的 —— 并不存在一个要去达成共识的、
  真正的标量「`R` 的带宽」，只存在*某个给定客户端在某个给定时刻经某条给定路径
  所达成的吞吐量*（GR-18）。客户端必须（MUST）将一个未经探测的中继的 `bw` 声称
  视作**低带宽默认值**（PS-7），绝不视作它的数字；一项客户端未曾亲自测量过的声称，
  在选择中承载的权重为零。

- **GR-12（探测是一次经由链路的封闭往返 —— 探测者从不被指名）。**
  `[claim-critical]` 探测必须（MUST）作为普通链路流量来承载：客户端构建一条链路，
  其**被测中继 `R` 处于中间跳**，发送一列有界的、整形为分享包形状的信元（第 1
  部分：定长 `P = 2048` 字节，SP-3），经 `R` 寻址，并在该列车经同一链路返回时测量
  其往返吞吐量。`R` 看到一个信元自其前驱抵达、向其后继离开 —— 恰如它为真实的
  被转发流量所见 —— 并**无法看到客户端**：探测者坐落在 `R` 视野之外至少一跳处，
  一如任何 Sphinx 链路（SP-4）。探测不得（MUST NOT）使用任何将其与被转发用户
  流量区分开来的信元类型、标志、长度或节奏（I-4，以及下方的 GR-13）。一个能把
  探测与载荷区分开来的中继，就能让探测通过而让载荷失败；所以，按构造，绝不能给
  它这个机会。

```
  经由链路的探测  （R 被测量；探测者从不处于 R 的视野之内）

   client（探测者）      guard G        relay R（受测）           tail T
   ───────────────      ───────        ──────────────            ──────
        │                  │                │                       │
        │  构建链路  C = [ G , R , T ]  （R 是中间跳）              │
        │─────────────────▶│                │                       │
        │     N 个定长信元之列车，与真实的被转发分享包              │
        │     不可区分（SP-3/SP-4，I-4）                            │
        │══════════════════╪═══════════════▶│══════════════════════▶│
        │                  │                │   T 回传该列车        │
        │◀═════════════════╪════════════════╪═══════════════════════│
        │   测量：bytes_acked / (t_last − t_first)  = 本次探测对 R、 │
        │          本条路径、本个时刻的吞吐量抽样                   │
        │                  │                │                       │
      vbw(R) ← 随时间对许多此类抽样作稳健聚合（GR-16）              │

   R 看到什么：  来自 G 的信元  →  发往 T 的信元。   与承载真实流量
   完全相同。  R **不**看到「client」，**不**看到「这是一次探测」，也
   无法只在被监视时才表现良好，因为它无法分辨自己正被监视。
   成本由探测者**支付**：它发送的 N·P 字节不会作为有用功收回
   （GR-14）。  R 无法被用来向受害者泛洪，因为该列车返回的是**探测者**，
   而绝非一个由攻击者指名的第三方（GR-15）。
```

### 5.2 探测必须具备的五条性质

- **GR-13（不可区分性 —— 一个中继无法只在被监视时才表现良好）。**
  `[claim-critical]` 其抗博弈性质是线上均匀性（I-4）：**探测流量必须（MUST）与一个
  中继被要求承载的真实被转发流量逐字节、逐时序不可区分**，使得该中继无法把其转发
  行为条件化于「我正在被测量吗？」。具体而言，探测信元必须（MUST）是完整的第 1
  部分分享包（`P = 2048` 字节，SP-3），必须（MUST）在一个真实发送方所用的同一
  批处理/抖动纪律之下发出（SP-6、SP-9），并且不得（MUST NOT）携带任何探测专用的
  标记。一个对真实流量服务不足、而对探测过度服务的中继，将不得不把二者区分开来；
  I-4 否决了它据以如此行事的信息。因此，所测得的 `vbw(R)` 是 `R` *会*为这个客户端
  的真实流量转发之量的一个下界，因为 `R` 无法把两者区分开 —— 而这正是全部要点
  所在：*请通过找出一个中继能据以作区分的比特来攻击这一点。*

- **GR-14（探测让探测者付出一个有界的、预付的量）。** 对 `R` 的一次探测必须（MUST）
  至多发送 `B_probe` 字节（strawman：`B_probe = 1 MiB`，铺展于 `≥ τ` 秒之上，
  `τ = 4 s`（s）），并且必须（MUST）被限速为每个目标中继至多一个在途探测，且每个
  客户端总共至多 `Q` 个并发探测（strawman `Q = 8`（s））。探测者花费的是它无法作为
  有用功收回的真实字节；这就是使探测自我限制的那项成本。客户端不得（MUST NOT）
  以比每 `T_probe` 一次更频繁的节奏探测一个中继（strawman：以小时计，而非以分钟计
  （s））—— 相对于一次测量老化的速度，带宽变化缓慢，因此频繁的重探测收益甚微、
  而成本线性增长（GR-16）。

- **GR-15（探测无法成为 DoS 放大器）。** `[claim-critical]` 被测中继必须（MUST）
  只把探测流量**回传给探测者，经其抵达的同一条链路**返回 —— 绝不回传给探测者的
  信元所能指名的任何地址。因为尾跳 `T` 把该列车沿 `C` 回传给构建了 `C` 的客户端，
  一次探测是一个**封闭回路**：一次探测所诱发的工作量以探测者自身所发送之量为界
  （放大系数按构造 ≤ 1，而非按策略），并且不存在任何字段能让攻击者在其中写入受害者
  的地址以令 `R` 向其泛洪。这是与任何「请中继向地址 X 发送一条测试流」式设计的
  结构性区别，那种设计会是一个反射器，是被**禁止**的：探测不得（MUST NOT）接受一个
  它自身不予终结的目的地。一个让探测得以瞄准第三方的实现是不合规的。

- **GR-16（一次探测测量一个路径-时刻；`vbw` 是许多次的稳健聚合）。** 单次探测是
  *一条路径在一个瞬间*的抽样，受守卫与尾跳各自容量、受横向流量、以及受 `C` 上任何
  一处拥塞的污染。因此客户端必须（MUST）（a）经**若干条相互独立的链路**探测 `R`
  （各不相同的守卫与尾跳，并在可能处按 GR-8 作来源混合），（b）把跨这些链路、在一个
  窗口内**所观测到的最大持续吞吐量**归于 `R`（取最大值，是因为任何单条链路的瓶颈
  都是 `R` 的一个*下界* —— 最快的路径最能隔离出 `R` 自身的容量），并（c）把结果当作
  一个**其置信度随年龄衰减的估计值**（strawman：半衰期为若干 epoch（s））。`vbw(R)`
  必须（MUST）被保守地加下界：一次未经佐证的单次探测算作低，而非高（PS-7 纪律）。

- **GR-17（探测结果不作为带宽被 gossip 出去；只有纪律是被共享的）。** 客户端
  不得（MUST NOT）发布、gossip 出去，或从一个对等体接受一个标量「`R` 的已验证
  带宽」—— 那将重建 I-3 所禁止的带宽权威（一个由对等体报告的数字是一项声称，
  不比 `bw` 本身更好，GR-9）。可以（MAY）被 gossip 出去的，是一个中继的
  **可达性/活性**，作为 GR-8 诸类别之中的一个来源类别，并且客户端可以（MAY）
  把一个对等体对某中继*存在且有响应*的认同用作一个佐证性视角（PS-15 式），但
  **每个客户端用于加权的吞吐量数字必须（MUST）是它自己的**（GR-11）。女巫对等体
  能够夸大*有多少*份报告声称「`R` 很快」，却无法夸大客户端自己的探测所测得之物
  —— 这就是把 GR-9/PS-10 的「只计已验证」规则应用于带宽。

### 5.3 一次探测能告诉你、和不能告诉你什么（诚实地降级）

- **GR-18（探测测量吞吐量，而非诚实、而非位置、而非身份）。** 一次探测回答
  *「这条路径能移动字节吗？」*此外无他。它不得（MUST NOT）被解读为如下各项的
  证据：
  - **该中继是诚实的** —— 一个中继可以把探测流量转发得完美无瑕，却仍然对真实
    流量作日志、延迟或关联；吞吐量与守卫+出口关联威胁（威胁模型）是正交的，后者由
    路径*不相交性*（第 3 部分）处理，而非由带宽处理；
  - **该中继就在地图所说之处** —— 探测为一次往返计时；它并不把 `R` 定位于某个
    AS 或司法辖区之中（那是第 8 部分的地图，PS-4，连同其各自申报的误差），而一次
    快速的探测对同址（co-located）只字未言（第 8 部分 §10）；
  - **该中继是一个单一的、各不相同的一方** —— 一个拥有真实容量的女巫运营者探测
    *得*与它本身一样快，因为它当真拥有那份带宽（见 §6：一个资源充沛的对手不是
    一个女巫，它是一个昂贵的真实对手）。
  一个合规的客户端必须（MUST）只按已验证带宽本来的样子呈现它 —— 一个随新鲜度
  衰减、受路径污染、由客户端自己测得的吞吐量估计值 —— 并且不得（MUST NOT）在任何
  选择决策中让一个很高的 `vbw` 替代不相交性（第 3 部分）或多样性（GR-8）。

## 6. 女巫与 eclipse，被界定（收紧 GR-8/GR-9）

身份是免费的（GR-9），所以一个对手可以随意夸大**原始的**记录计数。下面的防御
并不阻止这一点；它们界定这种夸大所*买到*的东西，而那个界限就是模拟器所测量的
曲线（§7.1）。

### 6.1 来自来源混合的 eclipse 界限

- **GR-19（GR-8 的上限给出一个被陈述的 eclipse 界限；其假设是类别独立）。**
  `[claim-critical]` 设客户端把其抽样跨 `m` 个相互独立的来源类别混合（GR-8：至少
  包括沿社交图谱的网桥、gossip 交换、直接探测 —— 故 `m ≥ 3`），并带有逐类别上限，
  即**没有任何单一类别贡献超过所存抽样的比例 `f`**（strawman `f = 1/2`（s））。设
  一个对手完全控制了这 `m` 个类别中的 `a` 个（经由一个被控类别投递的每一条记录
  都是敌意的），而在其余类别中毫无所控。那么该对手在客户端抽样中的份额以如下式
  为界
  ```
        A(a, f) ≤ min( 1 , a · f )
  ```
  一次**完全 eclipse** —— 对手供给客户端的整个视图，以至于每一个诚实中继都不可见、
  且路径选择只抽到对手链路 —— 需要 `A = 1`，故
  ```
        a ≥ ⌈ 1 / f ⌉       个处于对手完全控制之下的类别。
  ```
  在 strawman `f = 1/2` 之下，**完全 eclipse 要求对手拥有 ≥3 个类别中的至少 2 个**；
  拥有任何**一个**类别只能把对手封顶在抽样的 `f = 1/2`，而一次完全 eclipse 在
  **结构上是不可能的**（诚实类别仍投递视图的 ≥ `1 − f`）。这正是 GR-8 曾断言却未曾
  陈述的那个精确量：该上限把「eclipse」从「拥有足够多的中继」转化为「拥有足够多的
  *相互独立的类别*」，那是一个严格更难、且所需资源不同的问题。

- **GR-19a（点名那条假设，以及它在何处失效）。** GR-19 中的界限**仅当诸类别
  当真相互独立时**才成立 —— 即，攻破社交图谱网桥分发不会告诉对手任何关于 gossip
  对等体或探测目标的信息、也不给它对二者的任何控制。它恰恰**失效**于一方同时控制
  超过一个类别之时：
  - 一个**同时**拥有社交图谱网桥**与** gossip 对等体的对手，控制了 `a = 2` 个类别，
    并在 `f = 1/2` 处达到 `A = 1` —— 一次该上限并不阻止的完全 eclipse，因为该上限
    界定的是*逐类别*的量，而两个暗中为同一方的类别，并不是两个类别；
  - 相关性故障（一个托管服务商、一个司法辖区、两个名义类别背后的一套软件单一
    栽培）会无声地把 `m` 坍塌向 1。
  因此该上限的保护力**恰与诸类别的独立性一样强**，而一个合规的客户端必须（MUST）
  （a）使其各类别源自可明证地不同的信任源头（一个由朋友引介的网桥，若该朋友就是
  gossip 对等体，便不独立于 gossip），并（b）把一份诸类别*在一个异常视图上过于完美
  地相互一致*的抽样，视作与第 8 部分用于地图背离（ID-10）、第 3 部分用于操纵
  （PS-17）的同一个异常信号 —— gossip 它，不要信任它。独立性是一条**客户端必须主动
  维持的假设**，而非一条它凭计数类别就免费获得的性质。

### 6.2 女巫界限

- **GR-20（女巫夸大原始计数，绝不夸大已验证资源或真实边）。** `[claim-critical]`
  因为身份是免费的（GR-9），一个女巫对手把**原始记录计数**设为它喜欢的任意值。
  两个它**无法**夸大的客户端侧的量界定了损害：
  1. **它并不拥有的已验证带宽。** `vbw`（GR-11）是客户端自己的测量；一个由
     10 000 个零带宽身份构成的女巫测量下来就是 10 000 个已验证带宽约为 0 的中继，
     承载约为 0 的选择权重（PS-7）。要获得*权重*，对手就必须当真移动那些字节
     —— 见 GR-20a。
  2. **真实的社交图谱边。** 一个 Lox 式的网桥类别（GR-8）沿*人*的边传递信任；一个
     女巫能铸造身份，却铸造不出引介它们的那些边，因此社交图谱类别只以真实的人
     为之担保的速率接纳女巫（那正是该类别存在的全部理由）。
  其运行层面的后果是**PS-10，如今被量化**：可用规模估计必须（MUST）**只计
  独立已验证的中继与所观测到的 AS 多样性**，因此把原始计数从 `N` 夸大到 `10N`
  个女巫，使已验证规模估计移动**0**（没有任何女巫能通过验证），而一个客户端无法
  被诱骗进入其多样性是假的那套完整 `n, k` 参数。「只计已验证」买到了什么，用一行话
  说：**驱动参数选择的那个规模，在女巫夸大之下是不变的** —— 对手能让网络*看起来*
  任意地大，却改变不了客户端据以行动的任何东西。

- **GR-20a（一个资源充沛的对手不是女巫 —— 它是一个真实、昂贵、被接受的对手）。**
  `[claim-critical]` GR-20 的反面被诚实地陈述出来：一个**当真拥有**那份带宽、那份
  社交担保、以及那份 AS/司法辖区多样性的对手，**不**会被任何女巫防御击败，因为它
  **不是一个女巫** —— 它是一个为其各个位置付了钱的、货真价实的 `k`-路径对手。这是
  威胁模型早已接受的、被设计出来的残余风险（那个 `k`-路径条目：「把 `n`、`k` 提到
  合口味的程度」），而非本部分中的一个缺口。女巫防御把对手的成本从*免费*（铸造身份）
  抬高到*与所求影响力成比例的真实资源*；它们并不、也无法让影响力变得不可购买。客户端
  不得（MUST NOT）把「抗女巫」呈现为「拥有真实资源的对手无法取得位置」—— 前者为真，
  后者为假，且是一个不同的、被点名的、被接受的威胁。

## 7. 本设计未解决之事（OP-2 仍然开放）

**OP-2 在此并未被解决，上面也没有任何要求声称它被解决了。** 一个中央分配者
—— Tor 的带宽权威、Walking Onions 的签名快照 —— *本可*凭专断同时解决女巫与
eclipse：它会发布一份被信任的视图，女巫既无法注入其中、对手也无法向受害者投喂一份
它的私有视图。I-3 禁止那个分配者，因为那个能发布唯一被信任视图的一方，也正是那个
能被胁迫、被传票、或被查扣以发布一份*被投毒*视图的一方，而一个带有那个单点的发现
机制，正是整个项目所拒绝的那个一键关停开关。既已拒绝它，我们所剩下的便是一个
**界限，而非一剂解药**：

- **不存在任何仅凭 overlay 的机制能让 gossip 抽样完全抗女巫/抗 eclipse。** 上面
  每一项防御都是一种*客户端侧的资源验证或来源混合纪律*，而每一项都有一道被申报
  的接缝：
  - eclipse 界限（GR-19）只在类别独立之下成立，并在**一方拥有 ≥ `⌈1/f⌉` 个类别
    时坍塌**（GR-19a）—— 一个富到既能是那个把网桥递给你的朋友、**又**能是你与之
    gossip 的那些对等体的对手，会 eclipse 你，而 overlay 分辨不出「两个类别」与
    「一个一人分饰两角的一方」；
  - 女巫界限（GR-20）阻止*免费*夸大，却不阻止*付费*位置（GR-20a）—— 验证抬高
    成本，它并不封顶成本；
  - 带宽探测（§6）测量吞吐量，而非诚实或位置（GR-18）—— 一个中继可以在每次探测
    中都拿满分却仍是对手的，而一个拥有真实容量的快速女巫是一个真实的对手
    （GR-20a）。探测闭合了 GR-7 的*设计*问题；它并不闭合 OP-2。
- **eclipse 之下的 bootstrap 是那道艰难的残余。** 一个自其第一个联系人起便被
  eclipse 的客户端（GR-10），只看到对手类别，只把对手中继测量为「快」，并只听到
  对手的认同 —— 本部分中的每一个佐证机制都需要*一个诚实视角*才能运作，而一个
  从第一个数据包起就供给客户端整个世界的对手，否决了它那个视角。这与第 8 部分的
  TOFU bootstrap（ID-8）是同一个形状：诸防御在一个诚实来源一旦被触及时**检测**
  到一份坏视图，并使*永远*把一个客户端 eclipse 下去的代价昂贵 —— 它们并不**阻止**
  那次初始 eclipse。「检测，并使永久 eclipse 代价高昂」，而非「阻止 eclipse」，才是那个
  诚实的声称，也是 UI 所陈述的声称。

**该设计所精确做到的，是沿三个轴界定攻击：** 资源验证（GR-11/GR-20：免费女巫
什么也买不到）、来源混合（GR-19：eclipse 需要 ≥ `⌈1/f⌉` 个相互独立的类别，而不只是
许多中继），以及社交图谱（GR-20：边无法被铸造）。在这三者之后仍残余的是：**一个
拥有真实资源、跨多个当真看起来相互独立的类别拥有真实社交担保、并有能力供给一个
崭新客户端其整个第一视图的对手，能够女巫夸大它付了钱买来的影响力，并 eclipse 一个
它所包围的客户端 —— 而 overlay 无法从内部证明自己正被包围。** 那份残余就是 OP-2，
而它是开放的。

### 7.1 诸界限即模拟器的曲线

这些要求是可证伪的，而非修辞性的：一个女巫/eclipse 模型正由 `poc/sybil_sim.py`
连同 `network_sim.py` 现有的 `infer_error` 扫描一道被测量（该模拟器已对一份逐客户端的
局部 `gossip_sample` 建模 —— 那正是一个 eclipse 对手所塑形的视图 —— 并已把客观真相
与客户端的信念分离开来）。本设计的诸界限就是它必须（MUST）测量的那些曲线：

- **eclipse 曲线：** 对手样本比例 `A` 对被控类别数 `a`，它必须（MUST）贴合 GR-19 的
  `min(1, a·f)`，并且必须（MUST）在 `a = ⌈1/f⌉`（完全 eclipse）处显示那个拐点 ——
  且必须（MUST）显示在 `a = 1` 处诚实视图绝不低于 `1 − f`；
- **女巫夸大曲线：** 已验证规模估计（PS-10）对原始女巫计数，它必须（MUST）是
  **平的** —— GR-20 关于「夸大原始计数使已验证估计移动零」的声称，恰恰就是这种
  平坦性，而一条不平的曲线证伪 GR-20；
- **翻动交互：** eclipse 概率对抽样翻动率，因为一个重新抽样更快的客户端更早遇到
  一个诚实视角（「检测，使永久 eclipse 代价高昂」的声称是一个速率，而模拟器必须为之
  落实一个数字）。

若模拟器显示 eclipse 曲线胜过 `min(1, a·f)`，或女巫夸大曲线向上倾斜，那么该界限
就是错的、这项扩展就破了 —— 先攻击模型，再攻击这段文字。唯一一件无法被做成曲线的
事，是一个完全没有诚实视角的客户端的首次联系人 eclipse：它没有任何 overlay 内部的
测量，因为受害者按定义无法看到对手世界之外。它就是那份 OP-2 残余，被申报出来，
而它正是为何本部分说*界定*，而非*解决*。

## 此处引入的要求

- **GR-11** —— 已验证带宽是一项逐客户端的自我测量（`vbw`），绝非一个已发布或共享
  的数字；未经探测的声称算作低。
- **GR-12** —— 探测是一次封闭往返，被测中继处于中间跳；探测者从不处于中继的视野
  之内。
- **GR-13** —— 不可区分性：探测流量必须（MUST）与真实的被转发流量逐字节、逐时序
  相同（I-4），使得一个中继无法服务探测而饿死载荷。
- **GR-14** —— 一次探测让探测者付出一个有界的、预付的字节预算，按目标且整体地
  被限速。
- **GR-15** —— 探测是一个封闭回路（只回传给探测者）；它无法指名任何第三方目的地，
  因此无法放大成一个 DoS 反射器。
- **GR-16** —— `vbw` 是跨若干条相互独立链路的稳健聚合，取最大持续吞吐量，带有随
  年龄衰减的置信度与一个保守的下界。
- **GR-17** —— 吞吐量数字绝不作为带宽被 gossip 出去；只有活性/可达性是一个可共享
  的来源类别 —— 每个客户端按它自己的测量加权。
- **GR-18** —— 诚实降级：一次探测测量吞吐量，而非诚实、而非位置、而非各不相同的
  身份。
- **GR-19** —— GR-8 的上限给出 eclipse 界限 `A ≤ min(1, a·f)`；完全 eclipse 需要
  `a ≥ ⌈1/f⌉` 个被控类别（在 `f = 1/2` 处 ≥2）。
- **GR-19a** —— 该界限假设类别独立，并在一方拥有 ≥ `⌈1/f⌉` 个类别时失效；独立性
  是被维持的，而非免费的。
- **GR-20** —— 女巫夸大原始记录计数，却绝不夸大已验证带宽或真实社交边；已验证
  规模估计（PS-10）在女巫夸大之下不变。
- **GR-20a** —— 一个资源充沛的对手不是女巫，而是一个真实、昂贵、被接受的 `k`-路径
  对手；验证抬高成本，它并不让位置变得不可购买。

GR-11 与 GR-19 是那承重的两条：每个客户端测量它自己的带宽（没有权威），而来源
混合上限把 eclipse 从「拥有足够多的中继」转化为「拥有足够多的相互独立的类别」。
二者皆为**被界定的，而非绝对的** —— GR-11 的探测读不出诚实或位置（GR-18），而
GR-19 在诸类别暗中为同一方时坍塌（GR-19a）。OP-2 并未被解决：不存在任何仅凭
overlay 的机制能让 gossip 抽样完全抗女巫/抗 eclipse，而一个自其第一个联系人起便被
eclipse 的客户端，没有任何诚实视角去检测它。该设计从资源验证、来源混合与社交图谱
三处界定攻击；它并不消除攻击。那就是那份诚实的残余，而模拟器的曲线正是它被约束到
其自身数字的地方。像规范其余部分被攻破的那同一种方式来攻破它：找出一个中继能据以
作区分的探测比特（击败 GR-13）、一种探测能指名一个受害者的方式（击败 GR-15）、一个
能移动已验证规模估计的女巫（击败 GR-20），或一次在当真相互独立的类别之下胜过
`min(1, a·f)` 的 eclipse（击败 GR-19）—— 那你就攻破了这项扩展。
