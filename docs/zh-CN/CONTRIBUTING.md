# 为 ScrambNet 贡献

本项目处于规范前阶段。当前最有价值的贡献，按优先顺序排列：

1. **攻击威胁模型。** 针对 [docs/threat-model.md](threat-model.md) 中的任何论断提交一个
   issue，尤其是其中的开放问题清单。
2. **提议规范文本。** 针对 `docs/` 提交 PR——采用 RFC 风格，每个 PR 只讲一个机制。
3. **翻译。** README 已有六种语言；`docs/` 目前仅有英文。母语者的翻译与更正是第一等的贡献。
4. **指出既有成果。** 如果这里有什么在重新发明轮子，请点出那个轮子。本设计的理念是组合已发表、
   已受攻击的成果，绝不在引用就足够之处另行发明。

## 我们如何工作

- 每个 issue 只讨论一个主题。设计辩论留在 issues 中，决定记录在 `docs/`。
- 英文是 `docs/` 的权威语言；如果你修改了某一语言的 README，要么同步更新其他语言，要么在 PR
  中声明它们现已过时。
- 在威胁模型与线路规范稳定之前，不写任何代码。代码启动时：只有一个小而乏味、移动端优先的参考客户端。

## 化名政策

不要求真实姓名，而且永远不会要求。化名与匿名贡献都是第一等的。没有任何 CLA；通过贡献，你将你对文档的
贡献以 [CC0 1.0](../../LICENSE) 释出。

如果你自己的威胁模型有此需要，请保护好自己：

- 在提交中使用你所用 forge 的 noreply 地址：
  `git config user.email "USERNAME@users.noreply.github.com"`
- 以 UTC 提交，这样你的时区不会泄露：
  `git config alias.ci '!TZ=UTC git commit'`
- 不要用绑定你法律身份的密钥给提交签名；如果要签名，请使用专为这个化名创建的密钥。
- 不要复用你在别处用过的昵称，并且记住：行文风格本身就是一种指纹。

## 中立性

这个网络传输的是数据包，不是观点。它用同一套数学保护异见者及其对手；政治对手不是敌人。任何会让网络偏袒
或排斥特定观点、来源或目的地的提议，无论其观点如何，都将被拒绝——这种中立性既是本项目的伦理，也同样是
它的安全论据。
