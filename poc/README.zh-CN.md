# 分散核心 — 参考 PoC

[规范第 1 部分](../docs/spec/01-share-packet.md)与[第 6 部分](../docs/spec/06-rendezvous.md)的可执行伴侣。纯 Python 3，
仅用标准库，为被阅读和被攻击而写：这是一份可执行的规范，不是未来的节点。

它演示了什么：

- GF(2^8) 上逐字节的 (n, k) Shamir 分割，以及从任意 k 份份额的重建
  （SP-1、SP-2）；
- 用暴力枚举呈现无条件底线（I-2）：`floor_demo()` 枚举与已观察到的 k−1 份
  份额一致的每一个多项式，发现 256 个候选秘密字节*完全同等地一致*——即使
  算力无限，也什么都学不到；
- SP-7 收件人密钥标签（带密钥的 BLAKE2s）及其蕴含的标签窗口识别机制；
- SP-8 随机填充与第 1 部分 §4 的份额载荷格式；
- 诚实的代价：(n, k) 分散要传输 ×n 的密文体积（issue #4）。

运行：

    python3 dispersal.py        # 演示
    python3 test_dispersal.py   # 测试，含 vectors.json
    python3 rendezvous.py       # 第 6 部分演示：信箱与轮询
    python3 test_rendezvous.py  # 第 6 部分测试
    python3 network_sim.py      # 实验：k 路径对手 vs 网络规模
    python3 test_properties.py  # 性质的统计检验（均匀性、SP-7）
    python3 run_all.py          # 全部演示 + 全部测试，一个结论

## 实验：对手买到了什么，用数字说话

`network_sim.py` 把 issue #2/#4/#10 的开放问题变成一张表。它把一条消息建模为
经 4 条不相交链路、投向 4 个信箱的 n=4 份份额；k 路径对手拥有一部分中继，当
它同时掌握某条链路的 guard 与 exit 时，就「看见」了这条链路：

    发送方                                         信箱（各一份份额）
      |  份额 1 --[guard]--[mid]--[exit]-->  box 1  \
      |  份额 2 --[guard]--[mid]--[exit]-->  box 2   |  收件人取件，
      |  份额 3 --[guard]--[mid]--[exit]-->  box 3   |  任取 3 份，
      |  份额 4 --[guard]--[mid]--[exit]-->  box 4  /   重建消息

- **看见 >= k** -> 内容被攻破（且仅在此时；低于 k 时 I-2 底线在任何规模下
  都无条件成立）；
- **看见 < k** -> 内容安全，但每条被看见的链路仍泄露了*有*某个流经过——这
  正是威胁模型承认的元数据损失：分散能收窄它，但无法消除。

打印结果显示：内容被攻破的情形很罕见，并在网络增长到足以构建 AS 不相交链路
时消失；关联泄露虽小但非零，并且在*无法*构建此类链路的微小网络上最严重——
这正是年轻网络必须运行并公开声明降级「小网络模式」的原因（issue #4）。以上
为临时数值：请复现、攻破模型、到 issue 上辩论。

`vectors.json` 携带跨实现测试向量：能复现它们的实现即可在这一层互操作。

它**不是**什么：生产代码。没有常数时间运算、没有网络、没有洋葱层、没有
端到端 AEAD（按 SP-1，这一层只见到不透明的密文）。不要用它保护任何东西。
